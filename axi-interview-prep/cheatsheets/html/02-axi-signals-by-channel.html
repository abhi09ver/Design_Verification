AXI Signals, Channel by Channel

Every signal on the read and write channels: who drives it, how wide it is, and what it means.
M→Sdriven by master
S→Mdriven by slave
Naming trick: prefix = channel (AW, W, B, AR, R)
Ax* = same signal on both AW and AR

GGlobal signals & reset rules

SignalSourceDescription
ACLKClockSingle global clock; all inputs sampled and outputs changed on its rising edge.
ARESETnResetGlobal reset, active LOW. Can assert asynchronously; must de-assert synchronously to ACLK.
  • During reset: master drives ARVALID, AWVALID, WVALID LOW; slave drives RVALID, BVALID LOW.
  • VALIDs may go HIGH only at a rising edge after ARESETn is HIGH.
  • All other signals can be any value during reset.
No combinational path allowed from input to output on a master or slave interface (avoids loops across the interconnect).

WWrite data channel

SignalWidthSrcDescription
WIDimpl.M→SAXI3 only — ID of the write data (enables interleaving)
WDATA8…1024M→SWrite data; width = 8, 16, 32 … 1024 bits
WSTRBDATA/8M→SByte strobes — 1 bit per byte lane, HIGH = lane valid

WVALID1M→SWrite data & strobes are valid

No address on W — the slave links data to the address by order (AXI4) or by WID (AXI3).

BWrite response channel

SignalWidthSrcDescription
BIDimpl.S→MMust equal AWID of the transaction being answered
BRESP2S→MStatus of the whole write burst
BUSERimpl.S→MUser sideband (AXI4)
BVALID1S→MWrite response is valid
BREADY1M→SMaster can accept the response
One B per burst, not per beat. Slave sends it only after the last W beat (WLAST).

RRead data channel

SignalWidthSrcDescription
RIDimpl.S→MMust equal the ARID it is answering
RDATA8…1024S→MRead data

Read has no strobe — the master just ignores bytes it doesn't need. Slave must return all LEN+1 beats even if an error occurs.

Quick math: AxSIZE must not exceed the data bus width. 64-bit bus → max SIZE = 3'b011 (8 bytes).

→Read & write flows, step by step

Write (3 channels)
1 · AWVALID/AWREADY→2 · WVALID/WREADY × (LEN+1), WLAST→3 · BVALID/BREADY + BRESP
  • Master puts address/control on AW and raises AWVALID; slave takes it with AWREADY.
  • Master sends each beat with WDATA + WSTRB; WLAST on the final one.
  • Slave returns one BRESP with BID = AWID.
Read (2 channels)
1 · ARVALID/ARREADY→2 · RVALID/RREADY × (LEN+1), RLAST, RRESP each beat
  • Master puts address on AR; slave accepts with ARREADY.
  • Slave returns data beats with RID = ARID, RRESP per beat, RLAST on the last.
Example: 32-bit bus, read 16 bytes from 0x100 INCR → ARLEN = 3, ARSIZE = 3'b010, ARBURST = 2'b01 → beats at 0x100, 0x104, 0x108, 0x10C.

?Signal-level interview Q&A

QuestionCrisp answer
Which signals does the slave drive?All READYs on AW/W/AR, plus everything on B and R except BREADY/RREADY.
Why does W have no address?Address was already sent on AW; slave matches by order (or WID in AXI3).
Why no RSTRB?Master simply discards unused read bytes; reads have no side effect on lanes.
WSTRB width for 128-bit data?16 bits (one per byte).
Is RRESP per burst or per beat?Per beat. BRESP is per burst.
What must BID / RID equal?The AWID / ARID of the transaction being answered.
Can WSTRB be all zeros?Yes — a legal beat that writes no bytes.
Reset value of VALIDs?LOW; raised only after ARESETn goes HIGH.
Signals removed in AXI4?WID; locked transfers (AxLOCK reduced to 1 bit).
Signals added in AXI4?AxQOS, AxREGION, xUSER; AxLEN widened to 8 bits.
