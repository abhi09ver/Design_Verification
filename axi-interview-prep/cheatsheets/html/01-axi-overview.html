AXI Protocol: Channels, Handshake & Ordering

AMBA Advanced eXtensible Interface — 5 independent channels, burst-based, ID-tagged, multiple outstanding transactions.
Topic: Intro to AXI · AXI channels ·
In-order vs out-of-order transactions
Golden rule → transfer happens only when VALID & READY are both HIGH at a rising clock edge

1Where AXI sits in AMBA

BusUseTraits

Terminology: Master / Manager initiates, Slave / Subordinate responds. An interconnect connects many of each.

2Why AXI is fast

  • Separate address/control and data phases — address can be sent ahead of data.
  • Separate read and write channels — reads and writes run simultaneously (full duplex).
  • Burst transactions — only the start address is sent; slave computes the rest.
  • Multiple outstanding transactions — issue new addresses before earlier ones complete.
  • Out-of-order completion using transaction IDs.
  • Unaligned transfers & byte lanes via WSTRB.
  • Register slices can be inserted on any channel for timing closure (channels are independent).
One-liner: AXI decouples address, data and response so latency is hidden by pipelining and parallelism.

Write = 3 channels (AW, W, B). Read = 2 channels (AR, R) — read response rides on the R channel, so there's no separate read-response channel.

5VALID / READY handshake

  • Source drives VALID (info available); destination drives READY (can accept).
  • Transfer occurs on the rising edge where VALID = 1 and READY = 1.
  • Once VALID is asserted it must stay HIGH, with data/control stable, until the handshake completes.
  • Source must NOT wait for READY before asserting VALID (else deadlock).
  • Destination MAY wait for VALID before asserting READY; READY may also be asserted early and de-asserted before VALID.

6Channel dependencies

Write transaction
AW handshake+W … WLAST handshake→B response
  • W data may arrive before AW (slave may wait for both).
  • Slave must wait for WLAST (and in AXI4, AW too) before asserting BVALID.
Read transaction
AR handshake→R beats … RLAST
  • Slave must wait for ARVALID & ARREADY before asserting RVALID.
Deadlock-avoidance rules
  • Slave may wait for AWVALID/WVALID before AWREADY/WREADY.
  • Master must not wait for AWREADY/WREADY before driving W/AW VALID.
  • Master may wait for BVALID before BREADY (but it's good practice to keep BREADY/RREADY high).
Count rule: #W beats per burst = AWLEN + 1, WLAST exactly on the last one. #R beats = ARLEN + 1, RLAST on the last.

4 KB rule: a burst must never cross a 4 KB address boundary (a slave region is ≥ 4 KB, so a burst stays in one slave).
WRAP rules: length 2, 4, 8 or 16 only; start address must be aligned to transfer size.
Worked WRAP example
WRAP, 4 beats, 4 bytes/beat, start 0x38 → container = 4 × 4 = 16 B → lower boundary = INT(0x38/16)×16 = 0x30, upper = 0x40
0x38→0x3C→ wrap →0x30→0x34
Same with INCR: 0x38 → 0x3C → 0x40 → 0x44. With FIXED: 0x38 ×4.

9Transaction IDs: in-order vs out-of-order

The rule
Same ID → must complete in issue order.
Different IDs → may complete in any order.
  • ID = "ordering tag", typically one per master thread / stream.
  • The interconnect extends the ID with master-port bits so responses route back to the right master.
  • No ordering between reads and writes, even with the same ID — master must wait for a response if it needs that.
Example — master issues 3 reads
Issued:A · ID0B · ID1C · ID0
Legal:BAC✓ B overtakes (diff ID)
Legal:ABC✓ in-order
Illegal:CAB✗ C before A (same ID0)
Why out-of-order? A fast slave (SRAM) shouldn't be blocked by a slow slave (DDR). Different IDs let the fast response return first.
Outstanding & interleaving
  • Outstanding: master sends next AR/AW before previous data/response returns. Depth = how many in flight (read/write acceptance capability).
  • Read data interleaving: beats of bursts with different RIDs may be mixed; within one burst, beats stay in order.
  • Write data interleaving: AXI3 only (WID). AXI4: W beats must follow AW order, no interleaving.
  • In-order slaves simply return everything in issue order — always legal.
ModeProsCons
In-orderSimple slave & masterHead-of-line blocking
Out-of-orderHigher throughput, lower latencyReorder buffers, ID tracking

10How a DV engineer verifies AXI

Testbench (UVM AXI VIP)
  • Agent per interface: sequencer · driver · monitor; separate drivers/threads per channel so channels stay independent.
  • Monitor rebuilds bursts from beats; sends to scoreboard via analysis port.
  • Scoreboard: reference memory model + per-ID queues (assoc array keyed by ID) → checks same-ID order, allows cross-ID reordering.
  • Randomize READY delays (back-pressure) and VALID delays.
SVA protocol checks
  • VALID stays high & payload stable until READY: valid && !ready |=> valid && $stable(payload)
  • No X on VALID after reset; VALIDs low during reset.
  • WLAST/RLAST on beat LEN+1 exactly; no beat after LAST.
  • No 4 KB crossing; WRAP len ∈ {2,4,8,16}; WRAP addr aligned; BURST ≠ 2'b11.
  • BVALID only after AW + WLAST; RVALID only after AR; BID/RID match an outstanding ID.
Functional coverage
  • Cross BURST × LEN × SIZE, aligned vs unaligned, all WSTRB patterns.
  • All 4 responses, outstanding depth (0 … max), same-ID vs diff-ID reorder seen.
  • Handshake orderings a/b/c, back-to-back transfers, reads & writes concurrently.

11Rapid-fire interview Q&A

QuestionCrisp answer
How many channels? Why separate?5 (AW, W, B, AR, R); independent = parallel R/W, pipelining, register slices.
Why no read-response channel?RRESP travels with each R beat.
Max burst length?AXI4 INCR 256; AXI3 16; WRAP 16; FIXED 16.
Why the 4 KB boundary?Min slave address region; keeps a burst inside one slave & one page.
Can W come before AW?Yes; slave may buffer it.
Purpose of WLAST if LEN is known?Slave needn't count beats; simplifies logic & checking.
Why was WID removed in AXI4?Write interleaving was rarely used and complicated slaves.
How is out-of-order achieved?Different IDs; same-ID responses stay in order.
SLVERR vs DECERR?SLVERR from the slave; DECERR from interconnect when no slave decodes.
Who can deadlock and how?Source waiting for READY before VALID — forbidden.
AXI vs AHB in one line?AHB: one shared pipelined bus; AXI: split channels, outstanding, OoO.
Bytes in LEN=7, SIZE=3?8 beats × 8 B = 64 B.
