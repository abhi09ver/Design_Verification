3The DUT: axi4_slave_ram

Write FSM (as shipped)
WR_IDLEraise AW/W READY
WR_ADDRwait AW (+W same cycle)
WR_DATAwait W
WR_RESPBVALID until BREADY
Read FSM
RD_IDLEraise ARREADY
RD_ADDRAR → register RDATA
RD_DATARVALID until RREADY
  • Single outstanding per direction; reads and writes are independent FSMs.
  • apply_strobe() merges new bytes into the old word using WSTRB.
  • Index = (addr >> 2) % 256 — out-of-range addresses wrap (alias), no SLVERR.
  • RDATA is registered: it's stable while RVALID is held, which satisfies the handshake rule.
  • Memory initialised to 0 in an initial block (simulation only — not reset logic).

ConstraintWhat it doesInterview angle

Inline override: axi4_error_seq randomises with addr inside {[0x400:0xFFFC]} — but c_addr_legal still forbids that, so randomize() fails. Correct way: txn.c_addr_legal.constraint_mode(0) first, or put the range in a soft constraint.

660-second project pitch

"I verified an AXI4-Lite slave RAM — 256 × 32 with byte strobes — using a UVM-structured, self-checking testbench: agent with driver, monitor and sequencer, a scoreboard with a strobe-aware reference model, and functional coverage on addresses, strobes and responses.
When I stressed the handshake ordering I found the DUT deadlocks if write data arrives before the address, that it aliases out-of-range addresses instead of returning SLVERR, and that my regression could report PASS while the scoreboard logged errors. I fixed all three and added assertions so they can't come back."
Only say the second paragraph after you've applied the fixes from the next sheet. Then it's true, and it's your strongest story.

7Trace one write end to end

  1. Test calls seq_write(0x10, D) → item pushed to req_q, sequence blocks on rsp_q.
  2. Driver pops it, drives AWADDR/AWVALID + WDATA/WSTRB/WVALID on the next edge.
  3. Slave (WR_ADDR) sees both handshakes in one cycle, writes mem[4], raises BVALID.
  4. Driver raises BREADY, captures BRESP, puts the item on rsp_q → sequence unblocks.
  5. Monitor independently saw AW, W, B handshakes → builds its own item → ana_q.
  6. Scoreboard applies strobes to sb_mem[4], checks BRESP.
Key point: the scoreboard uses the monitor's item, never the driver's — so a driver bug can't hide a DUT bug.
