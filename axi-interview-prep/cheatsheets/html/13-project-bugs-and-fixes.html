#1Regression says PASS while the scoreboard logs FAILsTB · most important

Evidence (repo as-is): ALL TESTS DONE: PASS=6 FAIL=0 — yet the logs show scoreboard failures in 5 of 6 tests: read 7/1, rw 8/8, stress 30/2, error 1/1, wr_rd_chk 2/1 (pass/fail).
Root cause: scoreboard_report() only $displays "TEST FAILED"; vvp still exits 0, and the Makefile judges a test by exit code. So this testbench cannot fail.
Interview gold: "How do you know your test passed?" Answer: a non-zero exit / UVM_ERROR count checked by the regression script, and a check that the scoreboard compared more than zero items.
Fix (verified: failing run now exits 1 → make reports FAILED)
if (sb_fail == 0 && sb_pass > 0)
  $display("[SB] *** TEST PASSED ***");
else begin
  $display("[SB] *** TEST FAILED ***");
  $fatal(1, "scoreboard failures");   // non-zero exit
end
// UVM: fail in report_phase if UVM_ERROR count > 0,
// and grep the log for "UVM_ERROR :    0" in regression

#2Deadlock when write data arrives before the addressDUT · protocol violation

In WR_ADDR the slave holds WREADY high but only looks at AWVALID. A master that sends W first completes the W handshake — the slave drops the data. When AW arrives the FSM goes to WR_DATA and waits forever for a W beat that already happened.
Evidence: directed probe (W first, then AW, BREADY high) → NO BVALID after 50 cycles.
Why the TB missed it: the driver always raises AWVALID and WVALID in the same cycle. W-before-AW is legal AXI and the stimulus never produced it — a stimulus coverage hole, not a checker problem.
Fix: accept AW and W independently (verified: BVALID arrives)
assign awready = !aw_got && !bvalid;   // from own state only
assign wready  = !w_got  && !bvalid;
always_ff @(posedge aclk or negedge aresetn)
  if (!aresetn) {aw_got, w_got, bvalid} <= '0;
  else begin
    if (awvalid && awready) begin aw_addr <= awaddr; aw_got <= 1; end
    if (wvalid  && wready)  begin w_data <= wdata; w_strb <= wstrb; w_got <= 1; end
    if (aw_got && w_got && !bvalid) begin
      if (in_range) mem[idx] <= apply_strobe(mem[idx], w_data, w_strb);
      bresp  <= in_range ? 2'b00 : 2'b10;     // also fixes #3
      bvalid <= 1;  aw_got <= 0;  w_got <= 0;
    end
    if (bvalid && bready) bvalid <= 0;
  end

#3No SLVERR — out-of-range addresses aliasDUT

The header comment and the UVM scoreboard both expect SLVERR above 256 words, but the RTL indexes with (addr >> 2) % 256 and always returns OKAY.
Evidence: write DEADBEEF to 0x400 → BRESP = 00; then read 0x000 → DEADBEEF. The out-of-range write corrupted word 0.
error_test "passed" because it wrote and read the same aliased address — a self-consistent but wrong result. Classic reason to check against a spec-based model, not a DUT echo.
Fix: in_range = addr[31:2] < MEM_DEPTH. Write: skip the memory update, BRESP = 10. Read: RDATA = 0, RRESP = 10. Scoreboard expects SLVERR and doesn't update the model. Verified: both return 10, word 0 untouched.

#4Monitor records a bogus X transaction at start-upTB

Monitor loops on while (!(bus.arvalid && bus.arready)). At start ARVALID is X, ARREADY is 1 → condition is X → a while treats X as false and exits immediately, capturing a read with addr = X.
Evidence: [SB] FAIL READ addr=0xxxxxxxxx as the first scoreboard entry in 5 tests.
Fix (verified): 4-state compare while (!(bus.arvalid === 1'b1 && bus.arready === 1'b1)), and drive all master VALIDs to 0 from time 0, not after reset.
Concept: X-pessimism / X-optimism. if and while treat X as false; == returns X; === returns 0/1. Add an SVA "no X on VALID after reset".

#5Scoreboard model corrupts data on iverilogTOOL

sb_mem[idx][b*8+:8] = tr.data[b*8+:8] — a variable part-select on a class property. iverilog returns the low byte for every lane.
Evidence: 5-line repro: c.data = 40895E81 → model got 81818181. Same pattern in rw_test: exp=0x81818181 got=0x40895e81 — the DUT was right, the checker was wrong.
Fix (verified): copy into locals first: d = tr.data; st = tr.strb; then part-select d.
Lesson: prove the checker can catch a known-bad DUT, and when a mismatch appears, suspect the model as much as the RTL.

#7Coverage & stimulus gapsTB

  • WSTRB: comment says "all 15 patterns", covergroup has 10 bins, constraint can only generate 7 → 0010, 0100, 1000, 0111, 1110 are unreachable; coverage can never close.
  • No protocol coverage: handshake order (AW first / W first / same cycle) and back-pressure length are never measured — exactly where bug #2 hid.
  • READY never randomised: driver raises BREADY / RREADY at once; slave hold behaviour is barely exercised.
  • SLVERR bins unreachable while #3 exists — a coverage hole that would have flagged the bug if anyone had looked.
  • UVM scoreboard skips reads of never-written words — but the RAM resets to 0, so those could be checked.
  • End of test by fixed #100ns instead of waiting for the scoreboard to drain.
Coverage only tells you what you asked about. A 100% number on a weak plan proves little.
