Reading the RAM Back over AXI

Issue AR, collect LEN+1 beats on R, check RID / RRESP / RLAST on every beat, and compare against what was written.
AR handshake → R beats × (LEN+1)
RLAST only on beat LEN
write → read → compare = self-checking

1End-to-end flow of the project

1 · Resetall VALIDs LOW, ARESETn released on an edge
▶
2 · axi_write()AW ∥ W, then B · BRESP = OKAY
▶
3 · axi_read()AR, then LEN+1 R beats into a queue
▶
4 · Compareeach beat vs expected (model or write data)
▶
5 · Reporterror count → PASS / FAIL
The read must start after the B handshake of the write it depends on. AXI gives no ordering between reads and writes, even to the same address — waiting for BRESP is how the master guarantees it reads the new data.

2The axi_read task

task automatic axi_read(input  [ID_W-1:0]   id,
                        input  [ADDR_W-1:0] addr,
                        input  [7:0] len, input [2:0] size,
                        input  [1:0] burst,
                        output logic [DATA_W-1:0] rd_q[$]);
  rd_q.delete();
  // ---- read address channel
  ARID <= id;  ARADDR <= addr;  ARLEN <= len;
  ARSIZE <= size;  ARBURST <= burst;  ARVALID <= 1;
  do @(posedge ACLK); while (!ARREADY);
  ARVALID <= 0;

  // ---- read data channel
  for (int i = 0; i <= len; i++) begin
    do begin
      RREADY <= rand_bp ? $urandom_range(0, 1) : 1;
      @(posedge ACLK);
    end while (!(RVALID && RREADY));          // beat accepted
    rd_q.push_back(RDATA);
    if (RID   !== id)       $error("RID %0h != ARID %0h", RID, id);
    if (RRESP !== 2'b00)    $error("RRESP %b beat %0d", RRESP, i);
    if (RLAST !== (i == len)) $error("RLAST wrong at beat %0d", i);
  end
  RREADY <= 0;
endtask
  • Every beat is checked for RID, RRESP and RLAST — RRESP is per beat, unlike BRESP.
  • rand_bp = 1 randomly drops RREADY to exercise slave back-pressure handling.
  • RDATA is captured on the same edge as the handshake, so it's the data the slave was holding.

!Read-side mistakes

  • Starting the read before the write's BRESP → may read stale data.
  • Checking RRESP only on the last beat (it's per beat).
  • Not checking RLAST position — off-by-one bugs slip through.
  • Holding RREADY HIGH forever — never tests slave back-pressure.
  • Sampling RDATA without RVALID && RREADY at the same edge.
  • Expecting a narrow read to return only the requested bytes — the master must pick lanes.
  • Comparing against uninitialised memory (X) and calling it a pass because != returns X — use !==.

How many R beats for ARLEN = 7?8, RLAST on the 8th.
RRESP vs BRESP?RRESP every beat; BRESP once per burst.
Why wait for BRESP before reading?No R/W ordering in AXI; BRESP proves the write landed.
Why use !== in checks?Catches X/Z; != would give X and skip the error.
Best single test for the address logic?Write with WRAP, read with INCR (and vice versa).
