4Objections & end of test

task run_phase(uvm_phase phase);
  phase.raise_objection(this);
  seq.start(env_h.agent_h.sequencer_h);
  phase.drop_objection(this);
endtask

// instead of the repo's fixed #100ns:
function void end_of_elaboration_phase(uvm_phase p);
  uvm_phase run = uvm_run_phase::get();
  run.get_objection().set_drain_time(this, 200ns);
endfunction
  • run ends when every objection is dropped (plus drain time).
  • Drain time lets the last responses reach the scoreboard.
  • Better still: SB raises an objection while it has pending expected items.

6Sequence ↔ driver handshake

// sequence body()                  // driver run_phase
start_item(txn);       // wait grant   seq_item_port.get_next_item(txn);
txn.randomize() with {...};          drive(txn);
finish_item(txn);      // wait done   seq_item_port.item_done();
// optional response path
get_response(rsp);                    rsp.set_id_info(txn);
                                      seq_item_port.put_response(rsp);
  • Randomize between start_item and finish_item — late randomization can react to sequencer state.
  • get_next_item+item_done vs get (implicit item_done) vs try_next_item (non-blocking, for idle cycles).
  • Multiple sequences on one sequencer → arbitration (FIFO, weighted, random, strict…); lock / grab for exclusive access.
  • Virtual sequence on a virtual sequencer coordinates several agents; `uvm_declare_p_sequencer gives typed access.
  • Your repo's driver writes bresp / rdata back into the same item — works because the sequence holds that handle after finish_item.

8Interface, clocking block, modport

  input  awready, wready, bvalid, bresp,
         arready, rvalid, rdata, rresp;

  default input #1step;
  input awaddr, awvalid, awready, /* … all */;
endclocking
modport DRV (clocking driver_cb, input aresetn);
modport MON (clocking monitor_cb, input aresetn);
Your driver/monitor reference these, but the interface doesn't define them yet — this is the block to add.

9Other must-knows

  • Callbacks: hook into a driver (inject errors) without subclassing.
  • Report catcher: demote an expected UVM_ERROR in a negative test (e.g. SLVERR test).
  • Verbosity per component: +uvm_set_verbosity=… to debug one block.
  • Transaction recording to see items on the waveform.
  • uvm_event / uvm_barrier for cross-component sync.
  • Agent active/passive: is_active via config_db; passive agents reuse your monitor at SoC level.
