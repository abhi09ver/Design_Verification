Writing to the RAM from a Testbench

The testbench plays AXI master: it drives AW and W, waits for the handshakes, collects B, then checks memory.
drive with <= right after posedge
sample READY at the next posedge
AW ∥ W in fork…join, then B

2Clock, reset & idle values

initial ACLK = 0;
always #5 ACLK = ~ACLK;          // 100 MHz

initial begin
  ARESETn = 0;
  AWVALID = 0; WVALID = 0; WLAST = 0;
  BREADY  = 0; ARVALID = 0; RREADY = 0;
  repeat (5) @(posedge ACLK);
  ARESETn <= 1;                  // de-assert on an edge
  @(posedge ACLK);
  run_write_tests();
  $finish;
end
All master VALIDs must be LOW during reset and stay LOW until after ARESETn goes HIGH — the TB is the master, so this is your responsibility.

3The reusable axi_write task (SystemVerilog)

logic [DATA_W-1:0] wdata_q[$];   // filled by the test before calling
logic [STRB_W-1:0] wstrb_q[$];

task automatic axi_write(input [ID_W-1:0] id, input [ADDR_W-1:0] addr,
                         input [7:0] len, input [2:0] size, input [1:0] burst);
  fork
    begin : aw_ch                                  // ---- address channel
      AWID <= id;  AWADDR <= addr;  AWLEN <= len;
      AWSIZE <= size;  AWBURST <= burst;  AWVALID <= 1;
      do @(posedge ACLK); while (!AWREADY);      // handshake edge
      AWVALID <= 0;
    end
    begin : w_ch                                   // ---- data channel
      for (int i = 0; i <= len; i++) begin
        WDATA <= wdata_q[i];  WSTRB <= wstrb_q[i];
        WLAST <= (i == len);  WVALID <= 1;
        do @(posedge ACLK); while (!WREADY);     // one beat accepted
      end
      WVALID <= 0;  WLAST <= 0;
    end
  join

  BREADY <= 1;                                     // ---- response channel
  do @(posedge ACLK); while (!BVALID);
  BREADY <= 0;
  if (BID !== id)      $error("BID %0h != AWID %0h", BID, id);
  if (BRESP !== 2'b00) $error("BRESP = %b at addr %h", BRESP, addr);
endtask
fork…join runs AW and W at the same time. The TB raises WVALID without waiting for AWREADY — exactly what the protocol requires of a master (no "wait for READY before VALID").
do @(posedge) while(!READY) — after the edge, READY still shows the value the DUT had at that edge (the DUT's registers update later via NBA), so this samples the handshake correctly.
Non-blocking <= for every drive avoids races with the DUT on the same clock edge.
Payload is held automatically: nothing changes until the loop sees READY, so VALID-stable / data-stable rules hold.
Add a timeout around each wait (e.g. a parallel repeat(1000) @(posedge ACLK) + $fatal) so a stuck READY doesn't hang the sim forever.

6Checking the write

Option A · peek memory (quick)
if (tb_top.dut.u_ram.mem[addr >> 2] !== exp)
  $error("mem[%h] = %h, exp %h",
         addr, tb_top.dut.u_ram.mem[addr >> 2], exp);
Option B · read back over AXI (better)
Write, then axi_read() the same address and compare — tests the read path too and doesn't depend on internal names.
Option C · reference model
Keep a byte-array model in the TB; apply every write with WSTRB; compare on every read. This is the scoreboard idea, scaled up in UVM.
Always check BRESP and BID too — a "passing" write with SLVERR is a bug.

!Common testbench mistakes

  • Waiting for AWREADY/WREADY before raising VALID → can deadlock with some slaves.
  • Using blocking = on DUT inputs at posedge → race conditions.
  • Checking READY with wait(AWREADY) (level) instead of at a clock edge → miscounted beats.
  • Forgetting WLAST, or setting it on every beat.
  • Driving AW and W strictly in sequence only — never exercises W-before-AW.
  • Leaving BREADY LOW forever → write never completes.
  • Not filling wdata_q with LEN+1 entries.
  • No timeout → hung simulation instead of a clear failure.
  • Checking memory before B handshake has completed.
