The very first idea

What is an interrupt?

Story.

You are doing homework and waiting for a friend. You could get up every two minutes to check the door. Or you could keep working and let the doorbell tell you when they arrive. The doorbell is an interrupt.

The real words

An interrupt is a signal that says "stop what you are doing for a moment, something needs you". The CPU pauses its current program, runs a small piece of code called the interrupt handler, then goes back to where it was.

2
Why we need a helper

Why a controller?

Story.

A big school has hundreds of bells, phones and alarms, and many classrooms. If every bell rang in every classroom, nobody could study. So the school has a front office. Every bell rings at the office first. The office decides which classroom should hear it and how urgent it is.

The real words

A modern chip has many cores (small CPUs, each one is called a PE, processing element) and hundreds or thousands of interrupt sources. The Generic Interrupt Controller (GIC) is the front office. Arm wrote one rule book for it, the GIC architecture specification, so every Arm chip's GIC behaves the same way for software.

The GIC collects interrupts, picks the right core and the most urgent one, and tells that core.
3
Different kinds of bells

The four kinds of interrupt

Every interrupt has a number called its INTID (interrupt ID). The number tells you which kind it is.

SGI · a note from a classmateINTID 0 – 15

Software Generated Interrupt. One core sends a message to another core: "please wake up" or "please refresh your list".

PPI · your own alarm clockINTID 16 – 31

Private Peripheral Interrupt. Belongs to one core only, like that core's own timer. Every core has its own copy with the same number.

SPI · the school phoneINTID 32 – 1019

Shared Peripheral Interrupt. Comes from a shared device (UART, USB, DMA). The GIC can send it to any core you choose.

LPI · a letter in the postINTID 8192 and up

Locality-specific Peripheral Interrupt. Not a wire, a message written to memory by devices like PCIe cards. There can be thousands.

Numbers 1020–1023 are special "answers", not real interrupts. 1023 means "nothing for you right now". Newer GICs also have extra PPI and SPI number ranges (1056–1119 and 4096–5119).

4
How the signal looks

A doorbell press or a light left on

The real words

Edge-triggered: the GIC notices the moment the signal goes up. Level-sensitive: the interrupt is "on" for as long as the wire is high. With level, the handler must make the device lower the wire, or the interrupt comes straight back.

5
Hand up, answered, done

The life of one interrupt

Story.

A student raises a hand (pending). The teacher says "yes?" (acknowledge), and now the teacher is busy with that student (active). When the question is answered, the teacher says "done" (end of interrupt) and the student puts the hand down (inactive).

The real words

The CPU reads a register called ICC_IAR1_EL1 (Interrupt Acknowledge Register). The value it reads is the INTID it should handle. When it is finished, it writes that INTID to ICC_EOIR1_EL1 (End Of Interrupt Register). Message interrupts (LPIs) are simpler: they only have Inactive and Pending, so reading IAR finishes their state change.

The CPU has read IAR but has not written EOIR yet. What state is the interrupt in?
6
Fire alarm beats lunch bell

Who goes first: priority

Story.

If the fire alarm and the lunch bell ring together, you go with the fire alarm. And if you are in the middle of lunch and the fire alarm rings, you stop eating. But if a friend calls while you are handling a fire, they wait.

The real words

Each interrupt has an 8-bit priority. A smaller number means more urgent. The core has a Priority Mask Register (ICC_PMR_EL1): only interrupts with a number smaller than the mask can reach it. While the core is handling one interrupt, its running priority is that interrupt's priority, and only something more urgent can preempt (interrupt the interrupt).

PMR is 0xA0. A lunch bell with priority 0xC0 rings. What happens?

Finding the right classroom

  
Every core has an address

  
Story.
To deliver a note in a big school you need four parts: campus, building, floor, room. "Campus 0, building 1, floor 2, room 3" points to exactly one room.

  
The real words
Each core has an affinity address with four numbers: Aff3.Aff2.Aff1.Aff0, for example 0.0.1.3. The Distributor has one GICD_IROUTER register per SPI that stores the address of the core that should get it. You can also set a mode that means "any one free core", which spreads work around.
To send an SGI, a core writes the target addresses into ICC_SGI1R_EL1. It can also say "everyone except me".






10

  
Letters, not wires

  
The post office: LPIs and the ITS

  
Story.
A letter arrives with a sender name (which device) and a letter number (which event). The post office has address books. It looks up the sender, then the letter number, and finds out which room it must go to and what to call it.

  

  
The real words
A device writes to the ITS register GITS_TRANSLATER. The ITS uses the DeviceID and EventID to find the LPI number and the target Redistributor. LPI settings (priority, enable) are kept in a table in normal memory, so there can be many thousands of LPIs without huge chip area.

The principal's office

  
Secret rooms: groups and security

  
Story.
Some messages are for the principal only, some for the teachers, and some for everyone. Normal students cannot even read the principal's mail.

  

    
GroupSchool versionWho handles it

    
      
Group 0Principal's own mailThe most trusted firmware (EL3). Always arrives as FIQ.

      
Secure Group 1Locked staff roomThe secure world (for example a trusted OS that keeps keys safe).

      
Non-secure Group 1Regular classroomThe normal OS, such as Linux or Android.

    

  
The real words
Arm cores have two "doorbell" signals: IRQ and FIQ. Simple rule: an interrupt for the world the core is in right now arrives as IRQ. An interrupt for a different world arrives as FIQ, which goes to the firmware so it can switch worlds. Normal software cannot see or change secure interrupts.






12

  
Make-believe classrooms

  
Pretend computers: virtualization

  
Story.
One big classroom is split into pretend classrooms. A helper (the hypervisor) takes real messages and puts sticky notes on the right pretend desk. Later, the school gets a smarter post office that can stick notes on pretend desks by itself, without bothering the helper.

  
The real words
A virtual machine (VM) is a pretend computer running on real cores. In GICv3 the hypervisor writes virtual interrupts into list registers (ICH_LR<n>_EL2), the sticky notes. The VM reads them as if they were real. In GICv4, the ITS can deliver message interrupts straight to a VM (direct injection). If that VM is not running right now, a doorbell interrupt tells the hypervisor to schedule it.

Saving battery

  
Sleeping cores

  
Story.
Before a student naps, they tell the class monitor "I'm going to sleep". The monitor says "OK, I'll hold your messages". If something important comes, the monitor wakes them up.

  
The real words
Software sets ProcessorSleep in the GICR_WAKER register, then waits until ChildrenAsleep shows the CPU interface is quiet. Then power can be turned off. An interrupt for that core now creates a wake request to the power controller instead of an IRQ.

Being a detective

  
How engineers test a GIC

  
Design verification (DV) engineers make sure the chip follows the rule book before it is built, using simulation. Their job is to imagine what could go wrong and prove it does not.
