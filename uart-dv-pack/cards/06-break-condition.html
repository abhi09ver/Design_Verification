Break Condition

Line held low for longer than a whole character — a deliberate signal, not just a bad frame.
06

What it looks like (8N1 — one character time = 10 T)

IDLE
← one character time: start + 8 data + stop, every sample = 0 →
still low → BREAK
MARK
NEXT START
Definition: RX input stays at 0 for longer than one full character (start + data + parity + stop). Every sampled bit — data, parity, stop — reads 0, and the line keeps going.

Expected DUT behaviour (16550-style)

  • RX: set LSR.BI (bit 4); FE is typically set with it (spec-dependent).
  • Load one 0x00 character into the FIFO per break — not one per elapsed frame time.
  • Then wait for the line to return to mark (1) and a fresh valid start before receiving again.
  • Raise the receiver line status interrupt if enabled.
  • TX: LCR bit 6 "set break" forces TX low until cleared. Safe sequence: wait for TX empty, set break, hold the required time, clear.

Why break exists

  • Attention / out-of-band signal — e.g. console "break" to drop into a debugger or bootloader.
  • LIN bus — each frame begins with a sync break of at least 13 dominant (low) bits.
  • Autobaud / resync — a guaranteed reset point that can't occur in normal data.
  • Fault detection — a cut or shorted line reads as permanent 0, i.e. continuous break.
Break vs framing error: both have stop = 0. A framing error can have any data and the line rises soon after. A break has all-zero samples and stays low past the character time. Duration decides.

Break detector — a parallel thread with a timeout race

forever begin
  @(negedge vif.rx);  t0 = $realtime;
  fork begin                                   // isolate: disable fork kills only these
    fork
      wait (vif.rx === 1'b1);                  // line came back: ordinary frame
      #(cfg.char_bits * cfg.bit_time);          // char_bits = 1 + data + par + stop
    join_any
    disable fork;
  end join
  if (vif.rx === 1'b0) begin                   // still low after a full character
    in_break = 1;                              // frame sampler skips FE/baud checks
    wait (vif.rx === 1'b1);
    brk_bits = ($realtime - t0) / cfg.bit_time;
    `uvm_info("UART_BRK", $sformatf("break %0.1f bit times", brk_bits), UVM_MEDIUM)
    if (!brk_expected) `uvm_error("UART_BRK_UNEXP", "unexpected break")
    in_break = 0;
  end
end
The outer fork begin … end join wrapper matters: a bare disable fork also kills every other thread this process spawned — a favourite SV interview question.

Bugs this catches

  • RX pushes a 0x00 into the FIFO every character time during a long break → FIFO floods, overrun.
  • RX restarts on the first sample after break without waiting for mark → junk frame.
  • BI asserted but FE not (or vice versa) against the spec.
  • Checker floods the log with FE + baud errors during an intended break — suppress while in_break.
  • Break while FIFO is full: is the break char dropped and OE set?

Interview Q&A

Q. How is break different from sending 0x00?
0x00 has a stop bit of 1 after 9 low bits. Break has no stop bit — the line stays low past the whole character.
Q. How do you detect break in the TB?
Race a "line went high" wait against a one-character timeout; whichever finishes first decides.
Q. Why only one character per break?
Break is one event. Repeated 0x00 chars would look like data and fill the FIFO.
Q. Where else have you seen break used?
LIN's 13-bit sync break, bootloader entry, debug consoles.
