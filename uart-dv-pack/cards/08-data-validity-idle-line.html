Data Validity & Idle Line

Right bits, right order, right width — and a line that stays quietly high when nothing is sent.
08

Data validity — what to check

  • Bit order: LSB first on the wire. D0 follows the start bit.
  • Width: exactly 5, 6, 7 or 8 data bits as configured — no extra, no missing bit.
  • Unused bits: with 5–7 bit words, upper RBR bits read 0 (check the spec).
  • No X / Z sampled in data — always an error, never "don't care".
  • End-to-end: byte written to THR on one side = byte read from RBR on the other, in order.

The symmetric-bug trap

If the TB driver and monitor both send MSB-first, a DUT that also does MSB-first passes every test. Loopback tests have the same blind spot: DUT TX → DUT RX hides any mistake made in both.
Break the symmetry:
  • One directed test checks the raw waveform of 0x01: line must go high in the bit right after start.
  • Asymmetric patterns: 0x01, 0x80, 0x0F, 0xF0, 0xA5, walking 1s and 0s.
  • Build driver and monitor from the spec independently, ideally by different people.

Idle line — glitches near the start sample point

Glitch 1/16 bit
Rejected — high at mid-start.
Glitch 7/16 bit
Rejected — false start.
Glitch 9/16 bit
Accepted as start → all-1 data, so the frame decodes 0xFF (stop is high, no FE). Noise becomes data.
The exact accept/reject boundary depends on the sampler (single sample at tick 8, or 3-sample majority) — that boundary is a coverage bin, and the checker should flag any sub-half-bit pulse on a TX line.

Idle-line rules

  • TX = 1 in and right after reset. A low blip on reset looks like a start bit to the partner.
  • Never X / Z on TX once out of reset.
  • Gap between frames ≥ configured stop bits — the next start may not come early.
  • Reset or disable mid-frame: TX returns to 1 at once; RX throws away the partial frame silently.
  • Character timeout (16550: about 4 character times of silence with data in FIFO) — RX tells software leftover bytes are waiting.

SVA in the interface

// TX held at mark while in reset
a_idle_rst: assert property (
  @(posedge clk) !rst_n |-> tx === 1'b1);

// no unknowns once running
a_no_x: assert property (
  @(posedge clk) disable iff (!rst_n)
  !$isunknown(tx));

// a low pulse on TX lasts at least one bit
a_min_low: assert property (
  @(posedge clk) disable iff (!rst_n)
  $fell(tx) |-> (!tx)[*(BIT_CLKS-1)]);
BIT_CLKS = clocks per bit from the divisor. Use a sampled strobe instead of clk if the divisor changes at runtime.

Coverage model

Data values
0x00, 0xFF, 0x55, 0xAA, walking-1, walking-0, random — crossed with width 5–8.
Inter-frame gap
back-to-back (0 extra), 1 bit, short, long idle, > char-timeout.
Line disturbances
glitch width bins around half-bit, reset mid-frame, enable/disable mid-frame.

Interview Q&A

Q. All tests pass but the chip talks garbage to a real PC. Why?
Likely a symmetric bug — bit order, parity sense or polarity wrong in both DUT and TB. Check one frame against the spec by hand.
Q. Why must TX be high during reset?
The partner is already running; any low pulse is a start bit and produces a junk byte or framing error on its side.
Q. What does a character timeout solve?
With trigger level 8, the last 3 bytes of a message never reach the trigger. Timeout tells software to collect them.
Q. Why treat X on the line as an error rather than ignore it?
X usually means uninitialised or multiply-driven logic — a real silicon risk hidden by simulation optimism.
