0x53 = 0101_0011 → sent D0..D7 = 1,1,0,0,1,0,1,0. Four 1s, so even parity bit = 0. Receiver samples every bit at its middle (16× oversampling: edge + 8 ticks, then every 16 ticks).

Core concepts

  • Asynchronous: no clock wire. TX and RX each run a local baud clock that must agree within a few %.
  • Two signals: TX → RX crossed between devices, plus common ground. Full-duplex, point-to-point.
  • Idle = 1 (mark). A falling edge is the only way a frame can begin.
  • Start bit = 0: gives the receiver a fresh timing reference every frame, so drift never accumulates across frames.
  • Data: 5–9 bits (8 typical), LSB first.
  • Parity (optional): none / even / odd / mark (1) / space (0).
  • Stop: 1, 1.5 or 2 bits of 1 — guarantees a high level before the next falling start edge.
  • Notation: 8N1 = 8 data, no parity, 1 stop. 7E1, 8O2 likewise.

Baud = symbols/s. For UART one symbol = one bit, so baud = bit rate — but not throughput.

Deep dive — how the receiver locks on

  1. Synchronise RX to the local clock (2-FF synchroniser — RX is an async input).
  2. Detect 1→0 on the synchronised line; start a 0–15 tick counter.
  3. At tick 8 (mid start bit) re-sample. Still 0? Real start. Back to 1? False start — glitch rejected, return to idle.
  4. Sample every 16 ticks: D0..Dn, parity, stop — always mid-bit, maximum margin to both edges.
  5. Stop must read 1, else framing error. Then hunt for the next falling edge.
Some UARTs take 3 samples around mid-bit (ticks 7/8/9) and majority-vote for noise immunity.

Traps interviewers set

  • "Asynchronous means no clock at all" — wrong. Both sides have clocks; they just aren't shared.
  • Bit order: if driver and monitor are both written MSB-first, the test still passes. Check against a known asymmetric byte (0x01, 0x80).
  • Throughput ≠ baud: 8N1 spends 2 of every 10 bits on framing.
  • Flow control is separate: RTS/CTS (hardware) or XON/XOFF (in-band software).
  • Long frames (9 data + parity + 2 stop) shrink the clock-tolerance budget.

What a DV plan must cover

  • All frame configs: data 5–8, parity ×5 modes, stop 1/1.5/2 — and their cross.
  • Every supported baud divisor, plus min and max divisor.
  • Back-to-back frames with minimum stop (no idle gap).
  • Clock drift injection on the TB side.
  • Each error type: parity, framing, break, overrun, false start.
  • Loopback mode, FIFO enable/disable, interrupts, reset mid-frame.

Interview Q&A — say these out loud

Q. Why is the idle line high?
So the start bit produces a guaranteed falling edge, and a broken or shorted line (stuck 0) is detectable as a break rather than looking like idle.
Q. Why doesn't clock drift build up over a long message?
Each frame re-aligns on its own start edge, so error only accumulates across the ~10 bits of one frame.
Q. Why sample at mid-bit?
It leaves equal margin to both edges, tolerating up to ~half a bit of accumulated timing error by the last bit.
Q. What is a false start and why reject it?
A low glitch shorter than half a bit. Re-checking at mid-start stops noise from launching a garbage frame.
Q. Why 16× oversampling and not 1×?
Without a shared clock the RX must find the edge itself; 16× locates it to within 1/16 bit.
Q. How many errors can parity catch?
Any odd number of flipped bits. Two flips cancel out and go unseen — parity detects, never corrects.
