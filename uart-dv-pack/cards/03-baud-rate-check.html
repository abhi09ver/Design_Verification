Baud Rate Check

Is every bit the width it should be — and how wrong can it be before data breaks?
03

The formulas

T_bit = 1 / baud
divisor = round( f_clk / (16 × baud) )
actual = f_clk / (16 × divisor)
error % = (actual − target) / target × 100
The baud generator is a counter that emits one tick every divisor clocks; 16 ticks make one bit. Integer division is why real UARTs are never exactly on target.

Lines = mid-bit sample points, timed from one start edge. Error grows linearly; the stop-bit sample (9.5 T after the edge in 8N1) is the worst case.
1. Last sample must stay inside its bit: drift < 0.5 T over 9.5 T → < 5.26%.
2. Edge detection is only good to 1/16 bit: (0.5 − 0.0625) / 9.5 → ≈ 4.6% total.
3. Split between TX and RX clocks → ≈ ±2.3% each; rise times and noise eat more → design to ±2%.
4. Longer frames (8 data + parity + 2 stop) put the last sample later → tighter budget.

Robust checker — measure every edge gap, not a count

forever begin
  @(vif.rx);  t = $realtime;                       // any edge
  if (in_frame) begin
    gap = t - t_prev;
    n   = $rtoi(gap / cfg.bit_time + 0.5);         // nearest whole number of bits
    err = gap - n * cfg.bit_time;
    if (err < 0) err = -err;
    if (n == 0)                                     // pulse shorter than half a bit
      `uvm_error("UART_GLITCH", $sformatf("%0.1f ns pulse", gap))
    else if (err > n * cfg.bit_time * cfg.tol)       // tol e.g. 0.02
      `uvm_error("UART_BAUD", $sformatf("gap %0.1f ns ~ %0d bits, off %0.2f%%",
                 gap, n, 100.0 * err / (n * cfg.bit_time)))
  end
  t_prev = t;
end
Every bit boundary that has an edge gets checked, and long runs of equal bits are checked as n × T. Use realtime and 1 ps precision: 1e9 / 115200 = 8680.555… ns would round badly at 1 ns.

Weak approaches to call out

  • "Count transitions in a time window" — transition count depends on the data. 0x00 and 0xFF have almost none, so the measured rate is meaningless.
  • "Count loop iterations and compare to the expected count" — the loop always runs the expected number of times. It checks the checker, never the DUT.
  • Sampling only mid-bit hides small drift: the value is still right. You need edge timestamps to see the error before it breaks data.
  • Hard-coded baud parameter — take it from the config object so one checker covers every divisor.

Tests & coverage

  • DUT TX: program every divisor (incl. 1 and max); checker confirms measured T within tolerance.
  • DUT RX: TB driver gets a drift knob. Sweep 0, ±1, ±2, ±3, ±4.5, ±6%: data correct inside the budget, framing errors expected beyond it.
  • Change baud mid-traffic (divisor latch write) — first frame after must use new rate.
  • Coverage: baud bins × frame format; drift bins × pass/fail; divisor min / max / typical.
  • Autobaud (if supported): measure the start bit of a known char such as 0x55 (alternating bits).

Interview Q&A

Q. Mismatched baud — what does the RX see?
Small mismatch: nothing. Larger: late bits sampled in the wrong cell → wrong data, then stop bit read as 0 → framing error.
Q. Why measure edges instead of trusting data?
Data passes until the margin is gone. Edge timing shows a 3% error long before it becomes a data failure.
Q. How would you inject drift in the TB?
Driver uses bit_time × (1 + drift) from a randomised config field, or drives from a separate clock with ppm offset.
Q. Why 16× and not 8×?
Finer edge location (1/16 vs 1/8 bit) leaves more drift budget. 8× allows higher baud from the same clock.
