Deep dive — what parity can and cannot see

1 bit flipped
Detected — count changes parity.
2 bits flipped
Missed — flips cancel. Only the scoreboard catches it.
P itself flipped
Detected — looks the same as a data flip.
Which bit?
Unknown. Parity detects, never locates or corrects.
Formally: parity gives a minimum Hamming distance of 2 — detects any odd number of errors, corrects none. Need correction → Hamming / ECC. Need burst detection → CRC at a higher layer.

Checker — compute over the configured width only

function bit exp_parity(bit [8:0] data);
  bit x = 1'b0;
  for (int i = 0; i < cfg.data_bits; i++) x ^= data[i];   // 5..8 bits, never blindly 8
  case (cfg.parity)
    PAR_EVEN : return x;
    PAR_ODD  : return ~x;
    PAR_MARK : return 1'b1;
    PAR_SPACE: return 1'b0;
  endcase
endfunction

// in write(uart_item it)
if (cfg.parity != PAR_NONE) begin
  it.pe = (it.par !== exp_parity(it.data));
  if (it.pe && !it.pe_expected)
    `uvm_error("UART_PE", $sformatf("data 0x%0h par %b exp %b", it.data, it.par, exp_parity(it.data)))
end
Two ways to check — pick one, don't mix: compare P to the computed value, or XOR data with P and compare the result to 0 (even) / 1 (odd). XOR-ing P in and then comparing to P is a classic bug.

Tests & coverage

  • Injection enum in the item: {NONE, FLIP_PAR, FLIP_1_DATA, FLIP_2_DATA}.
  • Expect: PE set for FLIP_PAR and FLIP_1_DATA; PE clear but data mismatch for FLIP_2_DATA.
  • Each mode with data_bits 5, 6, 7, 8 — the width bug only shows below 8.
  • Change parity mode between frames (LCR write while idle).
  • Cross: parity_mode × data_bits × injection × FIFO position.
  • DUT TX side: verify generated P for all modes, incl. all-0 and all-1 data.

Common bugs (DUT and TB)

  • Parity computed over all 8 bits when 7 are configured (stale MSB leaks in).
  • Even / odd swapped — invisible if TB model has the same swap. Check against a hand-computed table.
  • Mark / space ignored: hardware sends computed parity instead of a constant.
  • Parity bit position off by one → RX also reports framing errors.
  • PE flag attached to the wrong FIFO entry.

Interview Q&A

Q. Why do mark and space parity exist?
Used as a 9th bit: in multi-drop links the parity slot flags "address byte" vs "data byte".
Q. How is parity computed in hardware?
An XOR tree (SV reduction ^), or a 1-bit toggle flop updated as each bit shifts out.
Q. If parity misses double errors, why verify them?
To prove the DUT does not flag them and that your scoreboard, not the checker, catches the corruption.
Q. Can a frame have both PE and FE?
Yes. Both flags are set for that character; report both, but treat the FE as the likely root cause.
