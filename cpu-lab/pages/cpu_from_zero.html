Wires and gates

build an adder from nothing · L01_adder.sv

A computer only knows two things: 0 (off) and 1 (on), like a light switch. Gates are tiny rules: AND says 'both on?', OR says 'any on?', XOR says 'exactly one on?'. Glue enough rules together and you can add numbers. We build a 1-bit adder, then copy it 32 times.

bitone 0-or-1combinationalno memory: output follows input instantlyassigna permanent wire connectiongeneratecopy hardware N times

Read the code

Read full_adder: sum is 1 when an odd number of inputs are 1. The carry goes to the next box, just like carrying in school maths.

// LEVEL 1 - Wires and gates: build a 32-bit adder out of 1-bit full adders.
// Combinational logic = no clock, no memory. Output changes when input changes.
module full_adder (input  logic a, b, cin,
                   output logic sum, cout);
  assign sum  = a ^ b ^ cin;                 // odd number of 1s -> sum is 1
  assign cout = (a & b) | (cin & (a ^ b));   // carry when at least two inputs are 1
endmodule

module adder32 (input  logic [31:0] a, b,
                output logic [31:0] sum,
                output logic        cout);
  logic [32:0] c;                            // carry chain: c[0] in, c[32] out
  assign c[0] = 1'b0;
  for (genvar i = 0; i < 32; i++) begin : g_bit   // 'generate' = copy hardware 32 times
    full_adder fa (.a(a[i]), .b(b[i]), .cin(c[i]), .sum(sum[i]), .cout(c[i+1]));
  end
  assign cout = c[32];
endmodule

The clock and memory

flip-flops remember · L02_counter.sv

The clock is a drumbeat: tick, tick, tick. A flip-flop is a notebook that may only write on the tick. Between ticks it keeps showing the old number. Everything in a CPU marches to this drum, which is why all parts stay in step.

clock edgethe instant the drum hits (0→1)always_ff'this block is flip-flops'<=non-blocking: all notebooks write togetherresetstart from a known value

Read the code

count <= count + 1 means: at the next tick, the new value is the old value plus 1. Use <= in always_ff and = in always_comb. Mixing them was a real source of races in the big core.

// LEVEL 2 - The clock and the flip-flop. Sequential logic REMEMBERS.
// A register only changes on the clock edge. Everything else is "next value" math.
module counter #(parameter int W = 4) (
  input  logic         clk, rst,   // rst: active-high, synchronous
  input  logic         en,
  output logic [W-1:0] count
);
  always_ff @(posedge clk) begin          // always_ff = "this is a flip-flop"
    if (rst)     count <= '0;             // <=  (non-blocking): every flop updates TOGETHER
    else if (en) count <= count + 1'b1;   // wraps 15 -> 0 by itself (4 bits)
  end
endmodule
Show the self-checking testbench
module tb_L02;

Why does the testbench check just AFTER the clock edge?

The flip-flop changes on the edge. Checking a moment later sees the new value; checking exactly on the edge is a race.

The ALU

the CPU's calculator · L03_alu.sv

The ALU (arithmetic logic unit) is a calculator with buttons: ADD, SUB, AND, SHIFT... In hardware all the answers are worked out at the same time, and the button (op) only chooses which answer leaves the box.

casepick one of many$signedtreat bits as a +/- number>>>shift that keeps the signenumnames instead of magic numbers

Read the code

SLT and SRA need $signed. Without it, -1 (0xFFFFFFFF) looks like a huge positive number.

// LEVEL 3 - The ALU: a big "case" that picks one math result.
package alu_pkg;
  typedef enum logic [3:0] {ADD, SUB, AND, OR, XOR, SLT, SLTU, SLL, SRL, SRA} alu_op_t;
endpackage

module alu import alu_pkg::*; (
  input  alu_op_t     op,
  input  logic [31:0] a, b,
  output logic [31:0] y
);
  always_comb begin
    unique case (op)                        // 'unique': simulator warns if no branch matches
      ADD:  y = a + b;
      SUB:  y = a - b;
      AND:  y = a & b;
      OR:   y = a | b;
      XOR:  y = a ^ b;
      SLT:  y = {31'b0, $signed(a) < $signed(b)};
      SLTU: y = {31'b0, a < b};
      SLL:  y = a << b[4:0];
      SRL:  y = a >> b[4:0];
      SRA:  y = $signed(a) >>> b[4:0];      // >>> keeps the sign bit only on a SIGNED value
      default: y = 'x;                      // never silently "do nothing" (see bug B03)
    endcase
  end
endmodule
Show the self-checking testbench
module tb_L03 import alu_pkg::*; ;
  alu_op_t op; logic [31:0] a, b, y, exp; int errors = 0;
  alu dut (.*);
  function automatic logic [31:0] model(alu_op_t o, logic [31:0] x, logic [31:0] z);
    case (o)
      ADD: return x + z;            SUB: return x - z;
      AND: return x & z;            OR:  return x | z;    XOR: return x ^ z;
      SLT: return ($signed(x) < $signed(z)) ? 1 : 0;      SLTU: return (x < z) ? 1 : 0;
      SLL: return x << z[4:0];      SRL: return x >> z[4:0];
      SRA: return 32'($signed(x) >>> z[4:0]);
    endcase
  endfunction
  initial begin
    logic [31:0] corner [5] = '{0, 1, 32'hFFFF_FFFF, 32'h8000_0000, 32'h7FFF_FFFF};
    for (int i = 0; i < 3000; i++) begin
      op = alu_op_t'($urandom_range(0, 9));
      a = (i % 3 == 0) ? corner[$urandom_range(0,4)] : $urandom;   // mix corners + random
      b = (i % 5 == 0) ? corner[$urandom_range(0,4)] : $urandom;
      #1 exp = model(op, a, b);
      if (y !== exp) begin errors++; if (errors < 5) $display("FAIL %s %h %h -> %h exp %h", op.name(), a, b, y, exp); end
    end
    $display("L03 alu: %s (%0d errors in 3000 checks)", errors ? "FAIL" : "PASS", errors);
    $finish;
  end
endmodule

Check yourself

Why does the ALU have a default branch?

So an unknown op can never silently 'do nothing'. In your big core, missing ops (andi, ori…) did exactly that and the instruction vanished (bug B03).

Is 0x80000000 bigger than 1?

Unsigned: yes (2147483648). Signed: no (it is -2147483648). The same bits, two meanings.

In your big core: Your core has 3 of these ALUs working in parallel.

The register file

32 lockers, one glued shut · L04_regfile.sv

Registers are the CPU's pockets: tiny, very fast storage for numbers it is working on. RISC-V has 32 of them, x0 to x31. Each cycle you can peek into two lockers and put something into one. Locker x0 is glued shut: it always reads 0, and anything you put in it disappears.

read porta window to peek inwrite porta slot to put inx0always zerowrite enable'actually write this cycle'

Read the code

Two guards protect x0: one on the write side (wa != 0) and one on the read side. Reads are combinational (instant); writes wait for the clock.

// LEVEL 4 - The register file: 32 numbered boxes. Read 2, write 1 per cycle. x0 is always 0.
module regfile (
  input  logic        clk,
  input  logic [4:0]  ra1, ra2,          // read addresses (combinational read)
  output logic [31:0] rd1, rd2,
  input  logic        we,                // write enable
  input  logic [4:0]  wa,
  input  logic [31:0] wd
);
  logic [31:0] r [32];
  always_ff @(posedge clk)
    if (we && wa != 0) r[wa] <= wd;      // writes to x0 are thrown away
  assign rd1 = (ra1 == 0) ? '0 : r[ra1];
  assign rd2 = (ra2 == 0) ? '0 : r[ra2];
endmodule
Show the self-checking testbench
module tb_L04;
  logic clk = 0, we; logic [4:0] ra1, ra2, wa; logic [31:0] rd1, rd2, wd, model [32];
  int errors = 0;
  regfile dut (.*);
  always #5 clk = ~clk;
  initial begin
    foreach (model[i]) model[i] = 0;
    for (int i = 1; i < 32; i++) begin @(negedge clk); we = 1; wa = i; wd = 0; @(posedge clk); end // clear
    repeat (500) begin
      @(negedge clk);
      we = $urandom_range(0,1); wa = $urandom_range(0,31); wd = $urandom;
      ra1 = $urandom_range(0,31); ra2 = $urandom_range(0,31);
      #1;
      if (rd1 !== model[ra1] || rd2 !== model[ra2]) begin errors++; $display("FAIL read"); end
      @(posedge clk);
      if (we && wa != 0) model[wa] = wd;
    end

endmodule

Check yourself

Why have a zero register at all?

It gives free constants and tricks: addi x5, x0, 7 means 'x5 = 7', add x5, x6, x0 means 'copy x6'.

You write x7 and read x7 in the same cycle. Which value do you get?

In this design, the OLD one, because the write lands at the clock edge. Real pipelines add a bypass so you get the new one.

In your big core: Your core calls this the ARF (architectural register file). Renaming (Level 8) is about NOT waiting for it.

Queues and handshakes

valid + ready · L05_fifo.sv

Think of a queue at a ticket counter. The person giving tickets raises a flag saying 'I have one' (valid). The counter raises a flag saying 'I have room' (ready). A ticket moves only when both flags are up on the same beat. If the counter is full, the giver must wait and keep holding the same ticket.

FIFOfirst in, first outvalid'I have data'ready'I can take it'back-pressureready=0 makes the sender wait

Read the code

count has one extra bit so it can say 'completely full'. Push and pop in the same cycle leave the count unchanged.

// LEVEL 5 - A FIFO with valid/ready: the "queue at the ticket counter".
// RULE: data moves ONLY when valid && ready are both 1 on the same clock edge.
module fifo #(parameter int DEPTH = 4, parameter int W = 8) (
  input  logic         clk, rst,
  input  logic         in_valid,  output logic in_ready,   // producer side
  input  logic [W-1:0] in_data,
  output logic         out_valid, input  logic out_ready,  // consumer side
  output logic [W-1:0] out_data
);
  logic [W-1:0] mem [DEPTH];
  logic [$clog2(DEPTH)-1:0] rd_ptr, wr_ptr;
  logic [$clog2(DEPTH):0]   count;               // one extra bit so it can hold DEPTH
  wire push = in_valid  && in_ready;
  wire pop  = out_valid && out_ready;
  assign in_ready  = (count < DEPTH);
  assign out_valid = (count > 0);
  assign out_data  = mem[rd_ptr];
  always_ff @(posedge clk) begin
    if (rst) begin rd_ptr <= 0; wr_ptr <= 0; count <= 0; end
    else begin
      if (push) begin mem[wr_ptr] <= in_data; wr_ptr <= wr_ptr + 1'b1; end
      if (pop)  rd_ptr <= rd_ptr + 1'b1;
      count <= count + push - pop;               // push AND pop in one cycle: count stays
    end
  end
endmodule
Show the self-checking testbench
module tb_L05;
  logic clk = 0, rst = 1, in_valid = 0, in_ready, out_valid, out_ready = 0;
  logic [7:0] in_data, out_data, q[$], nxt = 0; int errors = 0, popped = 0;
  fifo #(4, 8) dut (.*);
  always #5 clk = ~clk;
  initial begin
    @(negedge clk); rst = 0;
    repeat (400) begin
      @(negedge clk);
      in_valid = $urandom_range(0,1); in_data = nxt; out_ready = $urandom_range(0,1);
      #1;   // sample the handshake BEFORE the edge - after the edge the outputs have moved on
      if (out_valid && out_ready) begin                     // scoreboard: what comes out must
        if (out_data !== q[0]) errors++;                   // be what went in, in order
        void'(q.pop_front()); popped++;
      end
      if (in_valid && in_ready) begin q.push_back(in_data); nxt++; end
      @(posedge clk);
    end
    $display("L05 fifo: %s (%0d errors, %0d items passed through)", errors ? "FAIL" : "PASS", errors, popped);
    $finish;
  end
endmodule

A whole tiny CPU

fetch → decode → execute → write back · L06_tiny_cpu.sv

Now we have a calculator (ALU), pockets (registers) and memory, and we can build a CPU! A program is a list of instructions. The PC (program counter) is a bookmark pointing at the current line. Every cycle the CPU reads that line, works out what it means, does it, saves the answer, and moves the bookmark. A branch moves the bookmark somewhere else, which is how loops work.

PCbookmark: address of the current instructionopcodewhich kind of instructionimmediatea number written inside the instructionbranchjump if a condition holds

Read the code

The test program adds 1+2+…+10 with a loop, stores 55 to memory, loads it back, and checks that addi x5, x0, -1 gives 0xFFFFFFFF. Immediates are always sign-extended from bit 31. funct7 means something only for R-type instructions. Your big core broke both rules (bugs B01 and B02).

// LEVEL 6 - A whole (tiny) CPU in one cycle: fetch -> decode -> execute -> write back.
// Supports: addi, add, sub, and, or, xor, lw, sw, beq, bne.  (RV32I encodings)
// Reuses Level 3 (alu) and Level 4 (regfile).
module tiny_cpu import alu_pkg::*; (
  input  logic        clk, rst,
  output logic [31:0] pc
);
  logic [31:0] imem [64];                 // program (loaded by the testbench)
  logic [31:0] dmem [64];                 // data memory (word addressed: addr[7:2])

  // ---------------- FETCH
  wire  [31:0] instr  = imem[pc[7:2]];
  // ---------------- DECODE: slice the fields out of the 32-bit word
  wire  [6:0]  opcode = instr[6:0];
  wire  [4:0]  rd     = instr[11:7];
  wire  [2:0]  funct3 = instr[14:12];
  wire  [4:0]  rs1    = instr[19:15];
  wire  [4:0]  rs2    = instr[24:20];
  wire  [6:0]  funct7 = instr[31:25];    // ONLY meaningful for R-type (bug B01!)
  // immediates: ALWAYS sign-extended from bit 31 (bug B02!)
  wire  [31:0] imm_i  = {{20{instr[31]}}, instr[31:20]};
  wire  [31:0] imm_s  = {{20{instr[31]}}, instr[31:25], instr[11:7]};
  wire  [31:0] imm_b  = {{19{instr[31]}}, instr[31], instr[7], instr[30:25], instr[11:8], 1'b0};

  localparam OP_IMM = 7'b0010011, OP_REG = 7'b0110011, LOAD = 7'b0000011,
             STORE  = 7'b0100011, BRANCH = 7'b1100011;

  // ---------------- REGISTER READ
  logic [31:0] a, b, wb_data; logic we;
  regfile rf (.clk, .ra1(rs1), .ra2(rs2), .rd1(a), .rd2(b), .we, .wa(rd), .wd(wb_data));

  // ---------------- EXECUTE
  alu_op_t op; logic [31:0] alu_b, y;
  always_comb begin
    op    = ADD;
    alu_b = imm_i;
    case (opcode)
      OP_REG: begin
        alu_b = b;
        case (funct3)
          3'b000: op = (funct7 == 7'b0100000) ? SUB : ADD;
          3'b111: op = AND;
          3'b110: op = OR;
          3'b100: op = XOR;
          default: op = ADD;
        endcase
      end
      STORE:  alu_b = imm_s;              // address = rs1 + imm_s
      BRANCH: begin alu_b = b; op = SUB; end  // compare by subtracting
      default: ;                          // addi, lw: rs1 + imm_i
    endcase
  end
  alu u_alu (.op, .a, .b(alu_b), .y);

  // ---------------- MEMORY + WRITE BACK
  wire is_load = (opcode == LOAD);
  assign wb_data = is_load ? dmem[y[7:2]] : y;
  assign we      = (opcode == OP_IMM) || (opcode == OP_REG) || is_load;

  // ---------------- NEXT PC
  wire take = (opcode == BRANCH) && ((funct3 == 3'b000) ? (y == 0) : (y != 0)); // beq / bne
  always_ff @(posedge clk) begin
    if (rst) pc <= 0;
    else     pc <= take ? pc + imm_b : pc + 4;
    if (!rst && opcode == STORE) dmem[y[7:2]] <= b;
  end
endmodule

Check yourself

How does the CPU make a loop?

A branch at the bottom compares two registers and, if the condition holds, sets PC = PC + offset (negative offset = jump back).

Why is a single-cycle CPU slow?

The clock must wait for the longest path (fetch + decode + register read + ALU + memory + write) every single cycle, even for simple instructions.

Why simple CPUs wait

dependencies and the scoreboard · L07_scoreboard.sv

Faster CPUs work like an assembly line: a new instruction starts every cycle while older ones are still finishing. Problem: if add x4, x3 needs x3 and mul x3 hasn't finished, the add must wait. In a single-file line, everyone behind it waits too, even instructions that need nothing. A scoreboard keeps one 'busy' flag per register to know who must wait.

RAWread-after-write: a true needWAWwrite-after-write: two writersstallwait a cyclebusy bit'this register is being computed'

Read the code

The flag is set when an instruction starts and cleared when its result comes back. stall checks both sources and the destination.

// LEVEL 7 - Why simple CPUs wait: a "busy bit" scoreboard for an IN-ORDER pipeline.
// busy[r] = 1 means "someone is still computing register r".
// An instruction may start only if its sources are not busy (RAW) and its destination
// is not busy (WAW). If it must wait, EVERYTHING behind it waits too (in order!).
module scoreboard (
  input  logic       clk, rst,
  input  logic       issue_valid,             // instruction at the front wants to start
  input  logic [4:0] rs1, rs2, rd,
  output logic       stall,
  input  logic       wb_valid,                // a result came back
  input  logic [4:0] wb_rd
);
  logic [31:0] busy;
  assign stall = issue_valid && (busy[rs1] || busy[rs2] || (rd != 0 && busy[rd]));
  always_ff @(posedge clk) begin
    if (rst) busy <= '0;
    else begin
      if (wb_valid)                          busy[wb_rd] <= 1'b0;
      if (issue_valid && !stall && rd != 0)  busy[rd]    <= 1'b1;   // same-cycle set wins
    end
  end
endmodule

Renaming

ticket numbers instead of names · L08_rename.sv

In a restaurant two customers might both order 'pizza'. The kitchen doesn't track 'pizza'; it tracks ticket numbers. The CPU does the same: every result gets a fresh ticket (a tag). The rename table (RAT) remembers, for each register, which ticket will produce its newest value. If there is no ticket, the value is already sitting in the register file.

tag / ticketthe name of a future valueRATregister → newest ticketvalid bit'a ticket exists'committicket finished, value saved

Read the code

Two rules. (1) A separate valid bit: ticket 0 is a real ticket, never 'no ticket'. (2) When a ticket finishes, clear the entry only if it still points to that ticket; a newer ticket may have replaced it.

// LEVEL 8 - Renaming: give every result a fresh "ticket number" (tag).
// RAT[r] says: "the newest value of register r will come from ticket #tag".
// If RAT says nothing (valid=0), the value is already in the register file.
module rename_table #(parameter int NREG = 8, parameter int NTAG = 8) (
  input  logic clk, rst,
  // rename one instruction per cycle
  input  logic                      ren_valid,
  input  logic [$clog2(NREG)-1:0]   rs1, rs2, rd,
  input  logic [$clog2(NTAG)-1:0]   new_tag,      // ticket number handed out (ROB slot)
  output logic                      s1_pending, s2_pending,
  output logic [$clog2(NTAG)-1:0]   s1_tag, s2_tag,
  // a ticket is finished and its value is now in the register file
  input  logic                      commit_valid,
  input  logic [$clog2(NREG)-1:0]   commit_rd,
  input  logic [$clog2(NTAG)-1:0]   commit_tag
);
  logic                     map_valid [NREG];   // a SEPARATE valid bit: tag 0 is a real tag!
  logic [$clog2(NTAG)-1:0]  map_tag   [NREG];   // (using 0 to mean "none" was bug B04)
  assign s1_pending = map_valid[rs1];  assign s1_tag = map_tag[rs1];
  assign s2_pending = map_valid[rs2];  assign s2_tag = map_tag[rs2];
  always_ff @(posedge clk) begin
    if (rst) foreach (map_valid[i]) map_valid[i] <= 1'b0;
    else begin
      // clear ONLY if the mapping still points at the finishing ticket
      if (commit_valid && map_valid[commit_rd] && map_tag[commit_rd] == commit_tag)
        map_valid[commit_rd] <= 1'b0;
      // a new rename of the same register wins (written last)
      if (ren_valid && rd != 0) begin map_valid[rd] <= 1'b1; map_tag[rd] <= new_tag; end
    end
  end
endmodule

9

Waiting room and the bell

reservation station + CDB · L09_rs_cdb.sv

Order tickets wait on a rail (the reservation station) until all their ingredients are ready. When a cook finishes, they ring the bell and shout 'ticket 2 is ready, it's 30!'. That bell is the common data bus (CDB). Every waiting ticket listens: anyone who needs ticket 2 grabs the 30. As soon as a ticket has everything, it raises its hand, and the oldest raised hand goes to a cook. A younger, ready instruction can go before an older, waiting one. That is out-of-order execution.

RSwhere instructions wait for operandswakeupmatching your tag on the bellselectpick one ready instructionCDBthe shared result bell

Read the code

Two subtle cases are handled: tag 0 is a real tag (only the ready bit matters), and an instruction inserted on the same cycle the bell rings must catch it too, or it waits forever.

// LEVEL 9 - Reservation station + common data bus (CDB).
// Each waiting instruction listens to the CDB ("ticket #5 is ready, value 42!").
// When both operands are known it raises its hand; select picks the OLDEST hand.
module res_station #(parameter int N = 4, parameter int TW = 3) (
  input  logic clk, rst,
  // insert (from rename)
  input  logic          ins_valid,  output logic ins_ready,
  input  logic [3:0]    ins_op,
  input  logic          ins_a_rdy,  input logic [TW-1:0] ins_a_tag, input logic [31:0] ins_a_val,
  input  logic          ins_b_rdy,  input logic [TW-1:0] ins_b_tag, input logic [31:0] ins_b_val,
  input  logic [TW-1:0] ins_dst,
  // CDB broadcast
  input  logic          cdb_valid,  input logic [TW-1:0] cdb_tag,   input logic [31:0] cdb_val,
  // issue to the execution unit
  output logic          iss_valid,  output logic [3:0] iss_op,
  output logic [31:0]   iss_a, iss_b, output logic [TW-1:0] iss_dst
);
  typedef struct packed {
    logic busy; logic [3:0] op; logic [7:0] age;
    logic a_rdy; logic [TW-1:0] a_tag; logic [31:0] a_val;
    logic b_rdy; logic [TW-1:0] b_tag; logic [31:0] b_val;
    logic [TW-1:0] dst;
  } ent_t;
  ent_t e [N];
  logic [7:0] age_ctr;
  int free_i, pick;

  always_comb begin                                   // first free slot
    free_i = -1;
    for (int i = N-1; i >= 0; i--) if (!e[i].busy) free_i = i;
  end
  assign ins_ready = (free_i != -1);

  always_comb begin                                   // select: oldest ready entry
    pick = -1;
    for (int i = 0; i < N; i++)
      if (e[i].busy && e[i].a_rdy && e[i].b_rdy && (pick == -1 || e[i].age < e[pick].age)) pick = i;
  end
  assign iss_valid = (pick != -1);
  assign iss_op  = iss_valid ? e[pick].op    : '0;
  assign iss_a   = iss_valid ? e[pick].a_val : '0;
  assign iss_b   = iss_valid ? e[pick].b_val : '0;
  assign iss_dst = iss_valid ? e[pick].dst   : '0;

  always_ff @(posedge clk) begin
    if (rst) begin foreach (e[i]) e[i].busy <= 1'b0; age_ctr <= 0; end
    else begin
      // wakeup: every waiting operand compares its tag with the CDB (valid bit, NOT tag!=0)
      for (int i = 0; i < N; i++) begin
        if (e[i].busy && !e[i].a_rdy && cdb_valid && e[i].a_tag == cdb_tag) begin e[i].a_rdy <= 1; e[i].a_val <= cdb_val; end
        if (e[i].busy && !e[i].b_rdy && cdb_valid && e[i].b_tag == cdb_tag) begin e[i].b_rdy <= 1; e[i].b_val <= cdb_val; end
      end
      if (iss_valid) e[pick].busy <= 1'b0;            // leaves the RS when issued
      if (ins_valid && ins_ready) begin
        e[free_i].busy <= 1; e[free_i].op <= ins_op; e[free_i].dst <= ins_dst; e[free_i].age <= age_ctr;
        // also catch a broadcast that happens in the SAME cycle we are inserted (classic miss!)
        e[free_i].a_rdy <= ins_a_rdy || (cdb_valid && cdb_tag == ins_a_tag);
        e[free_i].a_val <= ins_a_rdy ? ins_a_val : cdb_val;
        e[free_i].a_tag <= ins_a_tag;
        e[free_i].b_rdy <= ins_b_rdy || (cdb_valid && cdb_tag == ins_b_tag);
        e[free_i].b_val <= ins_b_rdy ? ins_b_val : cdb_val;
        e[free_i].b_tag <= ins_b_tag;
        age_ctr <= age_ctr + 1;
      end
    end
  end
endmodule

Serve in order

the reorder buffer · L10_rob.sv

Dishes get cooked in any order, but customers must be served in the order they ordered. The reorder buffer (ROB) is a line of slots: new instructions join at the tail, finished ones are marked done, and only the one at the head (the oldest) may leave and update the real registers. This keeps the CPU's official state tidy at every moment.

ROBthe in-order lineheadoldest: commitstailnext free slotcommit / retiremake a result official

Read the code

It's a circular FIFO (Level 5 again!) plus a 'done' flag per slot. commit_valid = valid[head] && done[head].

// LEVEL 10 - The reorder buffer (ROB): finish in ANY order, retire in program order.
// Think of a restaurant pass: dishes may be cooked in any order, but they are
// served to the table in the order they were ordered.
module rob #(parameter int N = 8) (
  input  logic clk, rst,
  input  logic         alloc_valid, output logic alloc_ready,
  input  logic [4:0]   alloc_rd,    output logic [$clog2(N)-1:0] alloc_tag,
  input  logic         done_valid,  input  logic [$clog2(N)-1:0] done_tag,
  input  logic [31:0]  done_val,
  output logic         commit_valid, output logic [4:0] commit_rd,
  output logic [31:0]  commit_val,   output logic [$clog2(N)-1:0] commit_tag
);
  logic valid [N], done [N]; logic [4:0] rd [N]; logic [31:0] val [N];
  logic [$clog2(N)-1:0] head, tail;          // head = oldest (commit), tail = next free (alloc)
  logic [$clog2(N):0]   count;
  assign alloc_ready  = (count < N);
  assign alloc_tag    = tail;
  assign commit_valid = valid[head] && done[head];   // ONLY the oldest may leave
  assign commit_rd    = rd[head];  assign commit_val = val[head];  assign commit_tag = head;
  wire do_alloc = alloc_valid && alloc_ready;
  always_ff @(posedge clk) begin
    if (rst) begin foreach (valid[i]) valid[i] <= 0; head <= 0; tail <= 0; count <= 0; end
    else begin
      if (done_valid) begin done[done_tag] <= 1; val[done_tag] <= done_val; end
      if (commit_valid) begin valid[head] <= 0; head <= head + 1'b1; end
      if (do_alloc) begin valid[tail] <= 1; done[tail] <= 0; rd[tail] <= alloc_rd; tail <= tail + 1'b1; end
      count <= count + do_alloc - commit_valid;
    end
  end
endmodule

The whole restaurant

a tiny out-of-order CPU · L11_tiny_ooo.sv

Now glue Levels 8, 9 and 10 together. Orders come in one per cycle (dispatch). Each gets a ticket and a ROB slot, waits on the rail for ingredients, gets cooked when ready (ALU: 1 beat, MUL: 3 beats), rings the bell, and is served in order. Below is the real timeline from simulating it: instructions finish out of order and retire perfectly in order.

Read the code

Look at T4 (addi x5): it is ordered after the slow mul (T2) and the add that waits for it (T3), yet it finishes in cycle 7, before both. Then it waits, done, until cycle 12 to be served. x3 is written by two muls; the ARF ends with the second one's value (4), because commit is in order.

// LEVEL 11 - A tiny OUT-OF-ORDER CPU. Levels 8 + 9 + 10 glued together.
//   1 instruction dispatched per cycle, in order      (front of house)
//   4-entry reservation station, oldest-ready first   (the cooks' waiting rail)
//   1-cycle ALU (add, addi, sub) and 3-cycle MUL      (the cooks)
//   1 common data bus                                 (the bell: "ticket T is ready")
//   8-entry reorder buffer, 1 commit per cycle        (serve in order)
// Same ideas as your 3-wide core, small enough to read in 15 minutes.
module tiny_ooo (input logic clk, rst);
  // ------------------------------------------------------------------ state
  logic [31:0] imem [32];                       // program; a 0 word means "end"
  logic [31:0] arf  [32];                       // architectural registers (the "real" ones)
  logic        rat_v   [32];  logic [2:0] rat_tag [32];   // rename table (Level 8)
  logic        rob_v [8], rob_done [8];                    // reorder buffer (Level 10)
  logic [4:0]  rob_rd [8];    logic [31:0] rob_val [8], rob_pc [8];
  logic [2:0]  head, tail;    logic [3:0]  count;
  typedef struct packed {
    logic busy, is_mul, is_sub; logic [7:0] age; logic [2:0] dst;
    logic a_rdy; logic [2:0] a_tag; logic [31:0] a;
    logic b_rdy; logic [2:0] b_tag; logic [31:0] b;
  } rs_t;
  rs_t         rs [4];                                     // reservation station (Level 9)
  logic [31:0] pc;            logic [7:0]  age_ctr;
  logic        alu_v;         logic [2:0]  alu_tag;  logic [31:0] alu_res;  // ALU output register
  logic        mv [3];        logic [2:0]  mt [3];   logic [31:0] mr [3];   // 3-stage multiplier

  // ------------------------------------------------------------------ CDB: one result per cycle
  logic cdb_v; logic [2:0] cdb_tag; logic [31:0] cdb_val;
  always_comb begin
    cdb_v = mv[2] || alu_v;
    cdb_tag = mv[2] ? mt[2] : alu_tag;
    cdb_val = mv[2] ? mr[2] : alu_res;
  end

  // ------------------------------------------------------------------ decode the instruction at pc
  wire [31:0] ins   = imem[pc[6:2]];
  wire [6:0]  opc   = ins[6:0];
  wire [4:0]  rd    = ins[11:7], rs1 = ins[19:15], rs2 = ins[24:20];
  wire [31:0] imm   = {{20{ins[31]}}, ins[31:20]};
  wire        is_imm = (opc == 7'b0010011);              // addi
  wire        is_mul = (opc == 7'b0110011) && ins[25];   // funct7 = 0000001
  wire        is_sub = (opc == 7'b0110011) && ins[30];   // funct7 = 0100000

  // where does a source value come from?  register file / finished ROB entry / CDB now / wait
  function automatic void lookup(input logic [4:0] r, output logic rdy, output logic [2:0] tag,
                                 output logic [31:0] val);
    tag = rat_tag[r]; rdy = 1'b1; val = arf[r];
    if (r == 0)                                 val = 0;
    else if (rat_v[r]) begin
      if (rob_done[tag])                        val = rob_val[tag];  // finished, not yet committed
      else if (cdb_v && cdb_tag == tag)         val = cdb_val;       // finishing right now
      else                                      rdy = 1'b0;          // must wait for the bell
    end
  endfunction

  logic a_rdy, b_rdy; logic [2:0] a_tag, b_tag; logic [31:0] a_val, b_val;
  int free_rs, pick;
  logic disp_fire, iss_fire, commit_fire;
  always_comb begin
    lookup(rs1, a_rdy, a_tag, a_val);
    lookup(rs2, b_rdy, b_tag, b_val);
    if (is_imm) begin b_rdy = 1'b1; b_val = imm; end
    free_rs = -1;
    for (int i = 3; i >= 0; i--) if (!rs[i].busy) free_rs = i;
    disp_fire = (ins != 0) && (count < 8) && (free_rs != -1);
    // select: oldest ready entry. An ALU op may not start if a MUL will use the CDB
    // in the same cycle its result appears (structural hazard on the single CDB).
    pick = -1;
    for (int i = 0; i < 4; i++)
      if (rs[i].busy && rs[i].a_rdy && rs[i].b_rdy && (rs[i].is_mul || !mv[1]) &&
          (pick == -1 || rs[i].age < rs[pick].age)) pick = i;
    iss_fire    = (pick != -1);
    commit_fire = rob_v[head] && rob_done[head];
  end

  // ------------------------------------------------------------------ one clock edge
  always_ff @(posedge clk) begin
    if (rst) begin
      pc <= 0; head <= 0; tail <= 0; count <= 0; age_ctr <= 0; alu_v <= 0;
      foreach (rat_v[i]) begin rat_v[i] <= 0; arf[i] <= 0; end
      foreach (rob_v[i]) rob_v[i] <= 0;
      foreach (rs[i])    rs[i].busy <= 0;
      foreach (mv[i])    mv[i] <= 0;
    end else begin
      // 1. WRITEBACK: the CDB marks the ROB entry done and wakes up waiting operands
      if (cdb_v) begin
        rob_done[cdb_tag] <= 1'b1; rob_val[cdb_tag] <= cdb_val;
        for (int i = 0; i < 4; i++) begin
          if (rs[i].busy && !rs[i].a_rdy && rs[i].a_tag == cdb_tag) begin rs[i].a_rdy <= 1; rs[i].a <= cdb_val; end
          if (rs[i].busy && !rs[i].b_rdy && rs[i].b_tag == cdb_tag) begin rs[i].b_rdy <= 1; rs[i].b <= cdb_val; end
        end
      end
      // 2. EXECUTE: ALU result next cycle, MUL result after 3 cycles
      alu_v <= iss_fire && !rs[pick].is_mul;
      mv[0] <= iss_fire &&  rs[pick].is_mul;   mv[1] <= mv[0]; mv[2] <= mv[1];
      mt[1] <= mt[0]; mt[2] <= mt[1];          mr[1] <= mr[0]; mr[2] <= mr[1];
      if (iss_fire) begin
        rs[pick].busy <= 1'b0;
        alu_tag <= rs[pick].dst;  mt[0] <= rs[pick].dst;
        alu_res <= rs[pick].is_sub ? rs[pick].a - rs[pick].b : rs[pick].a + rs[pick].b;
        mr[0]   <= rs[pick].a * rs[pick].b;
      end
      // 3. COMMIT: only the oldest instruction may update the real registers
      if (commit_fire) begin
        if (rob_rd[head] != 0) arf[rob_rd[head]] <= rob_val[head];
        if (rat_v[rob_rd[head]] && rat_tag[rob_rd[head]] == head) rat_v[rob_rd[head]] <= 1'b0;
        rob_v[head] <= 1'b0; head <= head + 1'b1;
      end
      // 4. DISPATCH: rename + ROB slot + RS slot, in program order (written last: wins over 3.)
      if (disp_fire) begin
        rob_v[tail] <= 1; rob_done[tail] <= 0; rob_rd[tail] <= rd; rob_pc[tail] <= pc;
        if (rd != 0) begin rat_v[rd] <= 1'b1; rat_tag[rd] <= tail; end
        rs[free_rs] <= '{busy: 1, is_mul: is_mul, is_sub: is_sub, age: age_ctr, dst: tail,
                         a_rdy: a_rdy, a_tag: a_tag, a: a_val, b_rdy: b_rdy, b_tag: b_tag, b: b_val};
        tail <= tail + 1'b1; pc <= pc + 4; age_ctr <= age_ctr + 1;
      end
      count <= count + disp_fire - commit_fire;
    end
  end
endmodule

Check yourself

Why can't an ALU op start in the cycle a MUL is 2 stages along?

Both results would reach the single bell (CDB) in the same cycle. That is a structural hazard: not enough of a resource. Your big core uses 3 CDB lanes plus a completion buffer instead.

Name the three places a source value can come from at dispatch.

The register file (no ticket), the ROB (ticket finished but not yet served), or the CDB right now. Otherwise, wait for the bell.
