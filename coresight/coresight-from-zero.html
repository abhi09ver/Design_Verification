CoreSight from Zero

A chip is a tiny city where billions of things happen every second. CoreSight is the set of doors, maps, cameras and walkie-talkies that lets an engineer look inside that city. You need no background. We start with "what is a chip" and finish ready to test real hardware.

Level 1

The basics

What a chip is, what a bug is, and the two superpowers engineers use to find bugs.

1A chip is a tiny city of workers

Story

Imagine a city on a fingernail. Inside, a few very fast workers follow a recipe book one line at a time: "take this number, add that number, put the answer in box 7". They do this billions of times every second. There are also storage rooms full of numbered boxes.

Real words
Worker=CPU core or PE (processing element)
Recipe book=program, made of instructions
Numbered boxes=memory (addresses) and registers
The whole city=SoC (system on chip)
RememberA chip = many workers following instructions, very fast.

2Why bugs inside a chip are hard to find

Story

One day a worker puts the wrong answer in a box, or stops working completely. You want to know why. But the city is sealed inside plastic, it is far too small to see, and a billion things happen before you can blink. You cannot just walk in and look.

Problem 1: sealed box

You cannot open a finished chip and look at its wires.

Problem 2: too fast

By the time you look, billions of steps have passed. The clue is gone.

So chip designers build special helper hardware into the chip just for looking inside. ARM's name for this helper hardware is CoreSight. It sits next to the workers but does not do the real work itself.

RememberCoreSight = helper hardware built into the chip so engineers can see inside.

3Two superpowers: pause, or watch

Pause and poke

Shout "freeze!" to a worker. Now walk in, read its boxes, even change them, then say "carry on".

debug · this is invasive because it changes what happens.

Watch and record

Put a camera in each room. Workers never stop. Later, you replay the video to see exactly what they did.

trace · this is non-invasive because it only watches.

Story

A doctor can operate on you (pause and poke) or take an X-ray (just look). Some bugs disappear the moment you stop the worker, like a shy animal that hides when you open the door. For those, you need the camera.

RememberDebug = stop and look. Trace = record without stopping. Watching must never change the result.
Check yourself: a bug only happens when the chip runs at full speed. Which superpower do you use?
Trace. Stopping the worker changes the timing, so the bug may hide. Recording lets it run normally and you replay later.
Level 2

Getting inside

How you get in, how you find every room, and how you talk to each one.

4The front door, the receptionist and the hallways

Story

You plug a small box (a probe) into a few pins on the chip: that is the front door. Behind it sits a receptionist who understands your knock. The receptionist sends you down one of several hallways: one to the debug rooms, one to the storage rooms, one to old-style rooms.

Real words
Probe + pins=debug probe on JTAG (4–5 wires) or SWD (2 wires)
Receptionist=DP, the Debug Port
Hallway to debug rooms=APB-AP, an Access Port onto the debug bus
Hallway to storage=AXI-AP / AHB-AP, onto system memory
Hallway to old rooms=JTAG-AP, for older JTAG-only parts
Receptionist + hallways together=DAP, the Debug Access Port
RememberProbe → DP → AP → the room you want.

5Every room wears the same name badge

Story

Rooms are built by different companies, so how do you know what a room is? Rule of the city: every debug room has a name badge in the same spot, at the very back of the room. The badge starts with a secret handshake pattern so you know it is a real badge, then says what kind of room it is, who built it, its model number, and its version.

Real words
One room=one CoreSight component, a 4KB block of registers
Name badge=CIDR0–3 (component ID) and PIDR0–7 (peripheral ID), at offsets 0xFD0–0xFFC
Kind of room=CLASS: 0x1 = ROM table, 0x9 = CoreSight component
Who built it=JEP106 manufacturer code (ARM's is 0x3B)
RememberSame badge, same place, in every room. That is why one debugger tool works on every chip.

6The building map

Story

At the start, you only know where the building map hangs. Each line on the map says "walk N steps from here and you will find a room". You read lines one by one. A line can even point to another map on another floor. A line that is completely blank (zero) means the list is over.

Try it: read the mapMap hangs at address 0x8000_0000. Each step = 4KB (0x1000).
Press "Read next line" to start exploring.
Real words
Building map=ROM table
One line=ROMENTRY
Room address=map address + (OFFSET × 4KB). Offset can be negative (walk backwards).
Map on another floor=ROM table hierarchy
Where the first map hangs=BASE register in the AP
RememberFrom one starting address, a debugger can find every part of the chip by itself.
Check yourself: why is it a mistake for two maps to point to the same room?
The debugger would count the room twice and might set it up twice. The rule says every room appears exactly once, and maps must never point back in a circle.

7Talking to a room: mailboxes

Story

Every room has rows of numbered mailboxes. To give an order, you put a note in a mailbox ("camera: start recording"). To ask a question, you open a mailbox and read the note inside ("are you recording? yes"). You reach the mailboxes over a simple phone line that runs down the hallway.

Some rooms have a padlock on the mailboxes, so a confused worker cannot press buttons by accident. The password is a funny number: C5ACCE55 (read it as "SACCESS").

Real words
Mailbox=register (32 bits)
Put a note / read a note=write / read
Phone line=APB bus (the Debug APB)
Padlock=software lock: write 0xC5ACCE55 to LAR
Empty mailbox nobody uses=RAZ/WI: reads as zero, writes ignored
RememberEngineers control CoreSight by reading and writing registers over APB.
Level 3

Watching: the trace system

Cameras, the conveyor belt, merging lanes and the recorder room.

8Cameras

Camera on a worker

Writes down which recipe lines the worker ran, in a very short code so it fits.

ETM Embedded Trace Macrocell

Worker's diary

Software can write its own short notes: "starting task 5", "error 42".

STM System Trace Macrocell

Each recording is chopped into small boxes called packets. Anything that makes packets is a trace source.

RememberTrace sources (ETM, STM) turn activity into packets.

9The conveyor belt

Story

Packets ride a conveyor belt. The sender holds up a box and says "I have a box!". The receiver says "I'm ready!". Only when both are true does the box move. If the receiver is busy, the sender waits and keeps holding the same box. Nothing is dropped. Every box has a name tag saying which camera made it.

Try it: the beltTurn "Receiver ready" off and watch boxes pile up instead of falling off.
Camerasender
Recorder0 stored
VALID 0READY 1box moves no
Box moves only when VALID = 1 and READY = 1 together.
Real words
Conveyor belt=ATB, the AMBA Trace Bus
"I have a box!"=ATVALID = 1
"I'm ready!"=ATREADY = 1
Waiting without dropping=back-pressure / stall
Name tag=ATID, the trace source ID (0x01 to 0x6F)
RememberVALID and READY both high = transfer. Every box carries an ID.

10Merging lanes, copying, and the recorder room

Lane merger

Many belts join into one, taking turns fairly. funnel

Photocopier

One belt splits into two identical copies. replicator

Small shelf inside

A little on-chip memory that keeps the latest recording. ETB / ETF

Big warehouse

Saves recordings into the chip's main memory (DRAM). ETR

There is also a window to outside: pins that stream the recording to a capture box on your desk. That is the TPIU. Shelves, warehouses and windows are all trace sinks.

Stickers: why the formatter exists

Story

Inside the chip each box has its own name tag. But the window to outside only passes the boxes, not the tags. So before the window, a helper puts a sticker into the stream each time the camera changes: "the next boxes are from camera 1". The person outside reads the stickers and sorts the boxes back into separate videos.

Mixed boxes, tags lost:

abpqrcxyd

With stickers in the stream:

ID 1abID 2pqrID 1cID 3xyID 1d
Real words
Sticker helper=trace formatter
Packing=packed into 16-byte frames, costs about 6% extra space
"Start of a frame" marker=frame sync pattern 0x7FFFFFFF
RememberSource → belt (ATB) → funnel → sink. The formatter keeps the IDs when tags are lost.
Check yourself: if only one camera is recording, do you need stickers?
No. With one source there is nothing to sort, so the formatter can be switched off (called bypass mode) to save that 6%.

11One wall clock for everyone

Story

You have videos from four cameras. To know what happened at the same moment, each camera stamps the time from one big wall clock that everyone can see. If the clock shows 0, it means "clock not working", so do not trust that time.

Real words
Wall clock=timestamp, a 64-bit counter shared by all trace sources
Clock shows 0=timestamp UNKNOWN (source off or just reset)
RememberSame clock everywhere lets you line up recordings from different workers.
Level 4

Teamwork and safety

Freezing everyone together, locks and keys, and rooms with the lights off.

12Walkie-talkies: freeze everyone at once

Story

Worker 0 hits a problem and stops. But workers 1, 2 and 3 share the same boxes and keep running. By the time you look, they have changed everything. Fix: every room gets a walkie-talkie. When worker 0 stops, its walkie-talkie shouts on channel 0, and every other walkie-talkie tuned to channel 0 tells its worker to freeze too.

Try it: freeze gameEach number is how many recipe lines a worker has run.
Workers are running. Press the red-flag button.
Real words
Walkie-talkie in each room=CTI, Cross Trigger Interface
Radio tower joining them=CTM, Cross Trigger Matrix
Radio channel=channel (at least 4 recommended)
Signal into / out of a CTI=trigger in / trigger out
Steps others run before freezing=skid

The same walkie-talkies can also tell the recorder "stop recording now", so you capture exactly the moments around the problem.

RememberCTI + CTM pass short "event" messages between parts, like halt everyone or stop trace.

13Locks and keys: who is allowed in

Story

A phone you buy in a shop must not let strangers peek at secrets like passwords. So a guard holds keys. The pause key lets you freeze and poke. The watch key lets you record. The city also has a secret wing with its own two keys. Two simple rules: a pause key also lets you watch, and secret keys only work if you also hold the normal key.

Try it: hand keys to the guardTap a key to give it or take it back.
Real words
Keys=authentication signals
Pause / watch key=DBGEN / NIDEN
Secret pause / watch key=SPIDEN / SPNIDEN (Secure world)
Notice board showing which keys work=AUTHSTATUS register
Shop phone: keys melted away=signals tied low or blown fuses

Even with no keys, you can still read the name badges. The guard blocks what rooms do, not their badges.

RememberKeys decide what debug is allowed. Secure needs the normal key too.

14Rooms with the lights off

Story

To save electricity, the city turns off lights in rooms nobody uses. Walking into a dark room is a problem. Rules: the reception desk is never dark, so you can always knock. Before entering a room, ask reception to switch its lights on and wait for "done". And if you do knock on a dark room by mistake, it must answer "sorry, dark!" (an error), never stay silent, or you would wait forever.

Real words
Lights off=powered down power domain
Reception always lit=always-on domain
"Lights on, please" / "done"=power-up request / acknowledge
Room's light-switch number on the map=POWERID in the ROM entry
"Sorry, dark!"=PSLVERR error response on APB
Waiting forever=bus hang, a classic bug
RememberPower up before you access. A sleeping part must reply with an error, never hang.

15Put it all together: catching a real bug

Your phone app freezes once a day. Here is how an engineer uses everything you learned.

  1. Plug the probe into the front door. The DP answers. (Lesson 4)
  2. Ask for power-up so no room is dark. (Lesson 14)
  3. Read the ROM table and every name badge. Now the tool knows all rooms. (Lessons 5, 6)
  4. Check AUTHSTATUS: are we allowed to watch and pause? (Lesson 13)
  5. Write registers to give each ETM its own ID and turn on timestamps. (Lessons 7, 8, 11)
  6. Set up the funnel and the ETR warehouse so recordings are kept in memory. (Lesson 10)
  7. Program the CTIs: when any worker stops, freeze all and stop recording. (Lesson 12)
  8. Run until the freeze happens. Read the recording, sort by ID, line up by time, and see which worker did what just before. Bug found.
Level 5

Be the tester

What a verification engineer does, and your first tests for everything above.

16What is verification?

Story

Before a chip is built (it costs crores and months), its design exists only as code. A verification engineer builds a pretend world around that code, plays with it in every strange way possible, and checks every answer against a teacher's answer key. Your job is to be the naughty kid: press buttons in the wrong order, at the worst time, and prove nothing breaks.

Real words
Design as code=RTL (Verilog / SystemVerilog)
Pretend world=testbench, often built with UVM
Pressing buttons=stimulus, often random with rules (constrained random)
Teacher's answer key=reference model + scoreboard
"This must always be true" rule=assertion (SVA)
Checklist of things you tried=coverage
