CoreSight Field Guide

Debug and trace from architecture to sign-off: how a debugger finds, powers, unlocks and programs every component, how trace gets from a core to a pin, and what a senior verification engineer is expected to break along the way.

APB · program & discover ATB · trace data Event / channel · triggers Authentication Timestamp

Section refs like §C5.4 point into the spec. Material marked beyond spec comes from neighbouring ARM specs (ADI, ETM, CTI, TMC, ATB) that interviews expect you to know.

00The 60-second pitch

CoreSight is a plug-together debug and trace fabric. Every component exposes the same 4KB register frame so tools can identify it, a ROM table lets a debugger discover everything from one base pointer, APB programs it, ATB carries trace from sources through links to sinks, channels carry cross-triggers between CTIs, authentication signals gate what is allowed, and a shared 64-bit timestamp correlates it all. All of it must keep working while parts of the SoC are powered off.

Three layers of the architecture §A1.2

Part B · mandatory

Visible component

What a tool sees: the programmers' model (CIDR/PIDR, management registers at 0xF00–0xFFC) and topology-detection registers.

Part C · optional

Reusable component

Physical interfaces so IP from different vendors connects: APB, ATB, event, channel, authentication, timestamp. Skip it and tools still work, but integration and detection may fail.

Part D · system

System architecture

Clock and power domains, auth control, memory map views, connectors, trace formatter, ROM tables, topology detection and compliance classes.

Requirements to quote in an interview

The architecture must let you…

  • Access debug with no software running on the target
  • Connect to a running system without a reset
  • Trace non-invasively, with no effect on behaviour
  • Keep debug logic at minimal power when unused
  • Capture trace over long periods

…in a world where

  • Clocks and power of SoC regions change independently
  • On-chip monitors need the same access as an external debugger
  • Pins and trace storage are shared to save silicon
  • Platforms are nested and must hide their internals
  • Access must be controllable in the field

Unique Component Identifier §B2.1.2

CLASS + PART (12b) + JEP106 designer + REVISION + REVAND, plus DEVARCH and DEVTYPE for class 0x9. CMOD can no longer distinguish parts in v3.0. Any change to a component must bump REVISION or REVAND.

Reserved-space rules §B2.1.5

Unimplemented registers are RAZ/WI. Reads of WO and writes to RO count as reserved accesses. Anything unimplemented in 0xF00–0xFFF must read zero. Bigger components use 2n contiguous 4KB blocks (max 16,384 = 64MB); PIDR4.SIZE is deprecated.

Cold connect: what the debugger does §A1.4.2 §D8.2

  1. Connect the physical interface (JTAG/SWD) and talk to the DP.
  2. Request debug and system power-up; confirm clocks are running.
  3. Read the top-level ROM table pointer and its PIDR. Look up a saved description keyed by that PIDR; if found, stop here (non-invasive reconnect).
  4. Otherwise walk every ROM table, read CIDR/PIDR/DEVARCH/DEVTYPE of each entry, and look up the interfaces each known part has. Unknown parts are reported by JEP106 code and class, then ignored.
  5. Run topology detection: set ITCTRL.IME=1, drive each master's detection signal, see which slaves observe it, then clear IME.
  6. Reset the system (detection is invasive) and save the description.
// §D8.4 detection algorithm (condensed)
for each component c: ITCTRL.IME = 1                 // component preamble
for each interface type t:
  master_preamble(all m); slave_preamble(all s)
  for each master m:
    assert(m)                                        // ATB: ATVALID←1   Channel: CHOUT[0]←1
    for each slave s: if check_asserted(s) record(m→s)
    slave_post_assert(all s); deassert(m)
    for each slave s: if !check_deasserted(s) error  // stuck or shorted net
    slave_post_deassert(all s)
for each component c: ITCTRL.IME = 0                 // then reset the system

Why ATVALID? An intermediate bridge passes no control through while ATVALID is low, so it must be drivable for detection to cross non-programmable components §C7.3.1. DBGACK on the CoreETM interface may not be controllable on some cores, so DEVAFF registers can establish the PE↔ETM link instead.

04Reusable interfaces

Part C defines the wires. For each one, know what it carries, its clamp value when powered down, and the corner case it is famous for.

AMBA APB · Debug APB §C2.1

  • 32-bit, non-pipelined, slave stall (PREADYDBG), error (PSLVERRDBG)
  • PSLVERRDBG is only for "component not available", e.g. powered down
  • Clamps when off: PREADYDBG=1, PSLVERRDBG=1, PRDATA=0, so a dead slave answers with an error instead of hanging the bus
  • PADDRDBG[31] external/internal split is deprecated; use an address bit (bit 12 in the spec example) to separate views

AMBA ATB · trace transport §C2.2

  • Valid/ready stalling, byte-granular data (ATBYTES), source ID per beat (ATID)
  • Protocol-agnostic payload; check-pointing via flush (AFVALID/AFREADY) beyond spec
  • IDs 0x7B (flush response) and 0x7D (trigger) are also legal on ATB
  • Topology master wire: ATVALID; slave wires: ATVALID, ATREADY

Event interface §C3

  • Event = rising edge on EVENT, so at most one per two EVENTCLK cycles
  • Falling edge marks completion if the event has duration
  • No back-pressure: close events merge, especially when crossing into a slower clock

Channel interface §C4

  • Bidirectional, N channels (≥4 recommended), sync (CHCLK) or async (4-phase ACK)
  • A component's outputs reach every other component's inputs, never its own; inputs must not be reflected to outputs
  • Mismatched widths: connect a contiguous subset starting at channel 0
  • Not for counting fast events (instruction counts); fine for one-shot triggers and slow, handshaked signals such as IRQs

Timestamp interface §C6

  • TSVALUEB[63:0], natural binary, same value distributed to all components
  • 0 means UNKNOWN (source disabled or reset)
  • Components may use a subset of bits; resolution should be at least 10% of the fastest PE clock
  • Skew between domains is allowed and must be bounded in your system spec

Authentication interface §C5

  • DBGEN, NIDEN, SPIDEN, SPNIDEN, HIDEN, HNIDEN (+AUTHCLK/RESETn if synchronous)
  • Using a non-invasive enable requires importing its invasive pair
  • When a change takes effect is IMPLEMENTATION DEFINED; not precise around code regions
  • Async authentication is deprecated

05Authentication

CoreSight prevents unauthorized debug by disabling functionality, not by hiding registers §D2.2. Signals are tied low (production), tied high (prototype), fused, or driven by a challenge-response module.

Definitions §C5.2

Invasive: changes defined behaviour (memory writes, injecting instructions). Changing cycle counts is not invasive unless the cycles are architecturally defined.

Non-secure debug: anything Non-secure software could do on-chip. Measuring how long a Secure routine takes is Non-secure; changing how long it takes is Secure.

Equations to memorise Tables C5-2…C5-4

NS invasive     = DBGEN
NS non-invasive = DBGEN | NIDEN
S  invasive     = DBGEN & SPIDEN
S  non-invasive = (SPIDEN|SPNIDEN) & (DBGEN|NIDEN)
H  invasive     = DBGEN & HIDEN
H  non-invasive = (HIDEN|HNIDEN) & (DBGEN|NIDEN)

Three ideas generate all of these: invasive implies non-invasive; Secure requires the matching Non-secure enable; Secure and hypervisor enables are independent of each other.

06Trace formatter

A sink receives many ATB sources but a trace port has no ATID pins. The formatter wraps source IDs into a single stream of 16-byte frames that can be decoded even if the start is lost. §D4

byte 8ID / data · F

byte 14ID / data · F

Even bytes: bit 0 = F. F=1 → bits[7:1] are a new ID. F=0 → bits[7:1] are data and the missing bit 0 lives in byte 15. For an ID byte, the aux bit says whether the next byte still belongs to the old ID (1) or the new one (0). ID in byte 14 takes effect next frame.

Special IDs §D4.2.4

0x00 null (padding) · 0x01–0x6F usable sources · 0x70–0x7A reserved · 0x7B flush response · 0x7C reserved · 0x7D trigger · 0x7E reserved · 0x7F never (clashes with sync)

Sync packets

Full frame sync: 0x7FFFFFFF (LSB first). Halfword sync: 0x7FFF, continuous mode only, marks an idle port and is discarded by the TPA.

Cost

~6% bandwidth (1 aux byte per 16) plus 1 byte per ID change. Repeat the current ID about every 10 frames so a decoder that lost the start can recover.

07Cross-triggering: CTI and CTM

The embedded cross trigger makes "halt every core when any core hits a breakpoint" and "stop trace capture on this event" possible in hardware. CTIs map local triggers onto shared channels; the CTM broadcasts channels between CTIs.

What makes cross-trigger hard to verify

  • Skid: how many instructions PE1 retires after PE0 halts. Measure it, bound it, cover it.
  • CDC: async channels between clusters at different DVFS points can merge or stretch pulses.
  • Level vs pulse: an output left asserted re-halts the core after restart until acknowledged.
  • Loops: input reflected to output on the same CTI is forbidden; check it.

Coverage that interviewers like

  • Every trigger-in × channel × trigger-out mapping, including many-to-one
  • Simultaneous triggers from multiple PEs in the same cycle
  • Channel gated off, CTI disabled globally, source PE powered down
  • Trigger arriving while target PE is in WFI, reset, or already halted

08Power, clocks and reset

Debug must survive the SoC powering itself down. CoreSight defines three default domains and three debugger requests. §D2.1

Power-domain IDs in ROM entries §D6.3 §D7.3

If an entry has POWERIDVALID=1, the debugger must request power for domain POWERID before touching that component, otherwise it may be off or power off at any time.

  • Class 0x1: use the power requestor (GPR) listed in the same table, which itself has no power ID and shares the ROM's domain.
  • Class 0x9 with DEVID.PRR=1: set DBGPCR<p>.PR, poll DBGPSR<p>.PS until 0b11 (powered, held on).

Reset request handshake §D7.4

  1. Write DBGRSTRR.DBGRR=1
  2. Poll DBGRSTAR.DBGRA until 1
  3. Write DBGRR=0
  4. Poll DBGRA until 0. Done.

With SYSRSTRR.SYSRR=1 the system is held in reset, but debug logic may only be reset briefly so the debugger can configure it (e.g. vector catch) before release.

Compliance demands §D9.2.1: all debug functionality visible with clocks running when Debug Power Up is requested, operational when System Power Up is requested, and reset to initial state on Debug Reset, except where hidden by security.

Sample assertions

// ATB: once valid, payload is stable until accepted
a_atb_stable: assert property (@(posedge atclk) disable iff(!atresetn)
  atvalid && !atready |=> atvalid && $stable({atdata, atid, atbytes}));

// ATB: legal source IDs only (0x00/0x70–0x7F never from a normal source)
a_atid_legal: assert property (@(posedge atclk) atvalid |-> atid inside {[7'h01:7'h6F], 7'h7B, 7'h7D});

// Auth: secure non-invasive gating matches the architecture
a_snid: assert property (@(posedge clk) secure_trace_active |-> (spiden|spniden) && (dbgen|niden));

// Async channel: 4-phase, ack follows request
a_chin_hs: assert property (@(posedge clk) $rose(chin[m]) |-> ##[1:MAXLAT] chinack[m]);

10Bug catalog

Real failure patterns to bring up when asked "tell me about a hard debug/trace bug". Each one maps to a check above.

power

Debugger hangs reading a sleeping core

Off-domain slave not clamped to PREADY=1/PSLVERR=1, so APB never completes and the DAP times out. Fix: clamp at isolation; test: access during every power state.

auth

AUTHSTATUS lies

A bus trace source wired to a Secure bus reports only Non-secure capability. The spec warns debuggers must tolerate this, but your SoC should not ship it. Test: equation model vs actual packet emission.

formatter

Delayed ID switch off by one

Aux bit for an ID byte inverted, so one byte per switch lands on the wrong source. Silent until decode. Test: ID change at each even byte with both aux values.

flush

Flush never completes

A funnel port starved during AFVALID, or a replicator waits on a disabled branch. Trace capture "stops" with data stuck in FIFOs. Test: flush with each port idle, busy, disabled.

trace ID

Two sources share an ATID

Software or reset default programs equal IDs, or uses 0x00/0x70+. Decoder interleaves streams. Check: unique-ID assertion across all enabled sources.

CDC

Cross-trigger lost at low DVFS

Pulse from fast cluster merges or vanishes crossing into a slow cluster; one core never halts. Test: random clock ratios, back-to-back triggers.

CTI

Core re-halts right after restart

TRIGOUT held as a level until CTIINTACK; tools forgot the ack or RTL ignores it. Test: restart without ack and with ack.

ROM

Debugger powers the wrong domain

POWERID tie-off swapped between two clusters, so accesses work only when both are on. Test: power each domain alone and access every component.

timestamp

Streams disagree on time

Timestamp sampled through an unsynchronised path or reset to 0 mid-run, so cross-core ordering inverts. Test: correlation checker with DVFS and TS gating.

integration

Integration mode left on

After ITCTRL.IME tests, outputs remain under register control and functional trace is dead until reset. Test: functional run after topology detection without reset should be flagged.
