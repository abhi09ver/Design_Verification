SMMUv3 Field Guide

The System MMU in one sitting: how it is built, how software drives it, where it breaks, and how a senior verification engineer would test it. Every section ends in something you can say in an interview.

00

The mental model

A CPU core's MMU translates addresses for the software running on that core. The SMMU does the same job for everything else that does DMA: GPUs, NICs, NVMe, accelerators, PCIe endpoints. It uses the same VMSAv8-64 page tables as the CPU, so the OS or hypervisor can share one set of tables between a process and its device.

"Who is asking?"

On a CPU the answer is the current EL plus TTBR/ASID/VMID held in system registers. On an SMMU it arrives with each transaction: a StreamID (which device) and an optional SubstreamID (which process context, the PCIe PASID).

Config lives in memory

SMMUv2 used a fixed number of register "context banks". v3 moved all per-device state into in-memory tables (Stream Table → STE → CD), so it scales to thousands of devices and contexts. This is why v3 is not backward compatible with v2.

Software talks through queues

No register-poke per operation. Software writes commands into a Command queue in memory; the SMMU writes faults into an Event queue and PCIe page requests into a PRI queue. All are circular buffers with PROD/CONS pointers.

One-line answer: "SMMUv3 is an IOMMU that maps a transaction's StreamID to an STE, optionally its SubstreamID to a CD, then performs a stage-1 (VA→IPA) and/or stage-2 (IPA→PA) walk using Armv8/v9 page tables, with in-memory configuration and queue-based software interface."

01

Where it sits in the SoC

Inputs on every transaction

  • StreamID: device identity (PCIe: from Requester ID). Size from SMMU_IDR1.SIDSIZE.
  • SubstreamID + SSV: process context (PCIe PASID). Size from SSIDSIZE.
  • SEC_SID: which Security state's tables to use.
  • Address, R/W/X, privilege, memory attributes.

Outputs

  • Translated PA (with NS/PA space), transformed memory attributes and shareability, MPAM PARTID/PMG.
  • Or an abort / RAZ-WI termination, or a stall waiting for software.
  • Event records, PRI requests, interrupts or MSIs.

The configuration walk: STE and CD

Before any page-table walk, the SMMU has to find out how to translate. That is a lookup indexed by the transaction's IDs.

STE.ConfigStage 1Stage 2Typical use
0b000Abort, no event recordedDevice quarantined / not yet assigned
0b100BypassBypassTrusted device, identity mapping
0b101TranslateBypassHost OS DMA API / SVA on bare metal
0b110BypassTranslateDevice passthrough to a VM, guest has no IOMMU
0b111TranslateTranslateNested: guest owns S1 (vIOMMU), hypervisor owns S2

STE fields that come up in interviews

  • V: invalid STE gives C_BAD_STE.
  • S1Fmt, S1CDMax: linear or 2-level CD table, number of SSIDs.
  • S1DSS: what a transaction without an SSID does when substreams are on: terminate, bypass S1, or use CD 0.
  • STRW: StreamWorld (NS-EL1, EL2, EL2-E2H, Secure, EL3) tags TLB entries.
  • EATS: ATS off, full ATS, or split-stage.
  • S1STALLD, S2S, S2R: stall and record controls.
  • SHCFG, MTCFG/MemAttr, INSTCFG, PRIVCFG: input attribute overrides.

CD fields that come up

  • TTB0/TTB1, T0SZ/T1SZ, TG0/TG1, IPS: same meaning as the CPU's TCR_EL1/TTBRn_EL1.
  • ASID, ASET: TLB tag; ASET decides whether broadcast TLBI from PEs applies.
  • MAIR, AA64, ENDI, HA/HD (HTTU).
  • A, R, S: abort vs RAZ/WI on terminate, record events, stall on fault.
  • A CD with V=0 or illegal fields gives C_BAD_CD; SSID ≥ 2S1CDMax gives C_BAD_SUBSTREAMID.
04

Translation and nesting

The page-table format is VMSAv8-64 (plus the LPAE VMSAv8-32 format at S1 if supported). Granule decides how the VA is sliced into level indices. Try it:

Stage 1 (VA → IPA)

Owned by the OS (or a guest OS). Tables from the CD. Tagged by ASID. TTB0 for the lower VA range, TTB1 for the upper. Permissions: AP, UXN/PXN, PAN, and in v3.4 permission indirection (PIE).

Stage 2 (IPA → PA)

Owned by the hypervisor. Table base from the STE (S2TTB). Tagged by VMID. Controls VM isolation, S2AP, memory type combining (or FWB), and in v3.4 permission overlays.

The CD fetch also needs an S2 walk when nested. This is why walk caches (caching partial S1 and S2 results) matter so much for performance.

Say this: "Nested translation multiplies walk latency. Designs cache intermediate S2 results and partial S1 walks separately, and the verification plan must cover invalidation of each cache type independently, because a stale walk-cache entry gives a wrong PA without any fault."

Canonical sequence: change an STE

1Write STE (respecting the 64-bit single-copy atomicity rules; make V=0 or a safe state first if many fields change).
2CMD_CFGI_STE (SID, Leaf)
3CMD_SYNC, wait for completion
4Now the new config is guaranteed to be used.

Canonical sequence: unmap a page

1Write invalid PTE, DSB
2CMD_TLBI_NH_VA (ASID, VA) or broadcast TLBI
3CMD_SYNC (SMMU TLBs clean)
4CMD_ATC_INV then CMD_SYNC (device ATC clean). ATC after TLB, or the device can refill the ATC from a stale TLB.

Command errors

On a bad command the SMMU stops consuming, sets CMDQ_CONS.ERR = CERROR_ILL, CERROR_ABT (abort reading the queue) or CERROR_ATC_INV_SYNC (ATC invalidation timed out), and raises GERROR.CMDQ_ERR. CONS points at the bad command. Software fixes it and acknowledges through GERRORN. ECMDQ (v3.3) gives each CPU or VM its own queue to remove lock contention.

Each incoming transaction can cause at most one event: either a configuration error (C_) or, if the config is valid, one translation fault (F_). Errors are found only when a real transaction uses the structure, never on prefetch.

Stage reporting

Translation faults record which stage faulted (S2 bit), the input address, and for S2 faults the IPA. A fault during the S2 walk of an S1 table address is a stage-2 fault with CLASS = TT fetch. Interviewers love: "the CD fetch faulted at S2, what is reported?"

Global errors (GERROR)

Not per-transaction: CMDQ_ERR, EVTQ_ABT_ERR, PRIQ_ABT_ERR, MSI write aborts, SFM_ERR (service failure mode). GERROR vs GERRORN uses a toggle handshake: a bit is active when the two differ. While EVTQ_ABT_ERR is unacknowledged, the Event queue is not writable.

07

TLBs, tagging and invalidation

What tags an entry

StreamWorld (from STE.STRW + Security state) + VMID + ASID (or global, nG=0) + VA. Entries are not tagged by StreamID, so two streams sharing a CD/ASID share TLB entries. All SMMU translations are treated as Common (CnP does not apply).

Broadcast TLB maintenance

With IDR0.BTM, the SMMU snoops the CPUs' TLBI over DVM. This lets the SMMU share page tables with a process (SVA) without the driver issuing SMMU commands. CR2.PTM opts out. CD.ASET marks ASIDs that should ignore broadcast.

Caches you must invalidate

  • Config cache: STE, CD, VMS → CMD_CFGI_*
  • TLB + walk cache → CMD_TLBI_*
  • Device ATC → CMD_ATC_INV
  • GPT / DPT caches → TLBI PA / DPTI

TLBI by VA also invalidates walk-cache entries for that VA unless Leaf=1.

Break-before-make

Changing size, output address or attributes of a live mapping needs: invalid → TLBI → SYNC → new entry. Skipping it can hit two entries at once and give F_TLB_CONFLICT or unpredictable results. v3.2 BBML1/2 relaxes this for block-size changes.

HTTU (hardware AF/dirty)

With CD.HA/HD the SMMU sets the Access flag and clears the read-only bit for DBM pages with an atomic read-modify-write on the descriptor. Verify: atomicity against concurrent CPU updates, no update on a faulting txn, correct stage, and S2 dirty for VM live migration (v3.5 adds HDBSS logging).

Classic interview trap: "Is a TLBI enough before reusing a freed page?" No. You also need CMD_SYNC (or DSB with BTM), the ATC invalidate for ATS devices, and the SYNC after that. Until the SYNC completes, in-flight transactions may still use the old translation.

08

PCIe: ATS, PRI and PASID

ATS: device-side TLB

The endpoint sends a Translation Request; the SMMU walks and returns a Translation Completion; the device caches it in its ATC and later issues Translated transactions (AT=Translated) that skip SMMU translation. Controlled by STE.EATS. Split-stage (EATS=0b10) returns IPA only and the SMMU still does stage 2. CR0.ATSCHK makes the SMMU check Translated traffic against STE.EATS.

PRI: demand paging for DMA

A device that got a "not present" ATS completion sends a Page Request (grouped into a PRG; the "Last" bit closes the group). The SMMU queues it in the PRI queue; the OS faults the page in and replies with CMD_PRI_RESP. On PRI queue overflow the SMMU auto-responds so the device is not left waiting.

PASID = SubstreamID

PASID selects the CD, so one device can work in many process address spaces (Shared Virtual Addressing). v3.4 adds PASID on Translated transactions. A GPU/accelerator interview will ask how SVA, ATS and PRI fit together.

1Device: ATS Translation Request (VA, PASID)
2SMMU: STE/CD lookup, walk. No mapping → completion with R=W=0 (not a fault event).
3Device: PRI Page Request(s) → SMMU writes 16B entries to PRIQ, IRQ to OS
4OS: handle_mm_fault, map page, CMD_PRI_RESP(Success)
5Device: re-issue Translation Request, cache in ATC, send Translated DMA
6Later unmap: TLBI → SYNC → ATC_INV → SYNC (with completion timeout → CERROR_ATC_INV_SYNC)
09

Security, virtualization and RME

Security states

SEC_SID selects the programming interface. Secure has its own register page (SMMU_S_*), Stream Table, queues and Event queue. Non-secure faults never produce Secure events and the reverse. v3.2 adds Secure stage 2 (SEL2).

Virtualization

Hypervisor owns S2 and the STE; guest owns S1 tables and CDs (nested). v3.2 VMS gives per-VM structures. v3.3 ECMDQ and v3.5 vSID→pSID translation and direct-mode ECMDQ let a guest's vIOMMU driver issue commands with less trapping.

RME: Granule Protection Checks

An SMMU with RME has a Root interface (SMMU_ROOT_*, GPCEN). Every output PA is checked against the Granule Protection Table, same format as the CPU's FEAT_RME. A GPC fault on a client access is returned to the device like an external abort and is not written to the Event queue; details go to SMMU_ROOT_GPF_FAR. An ATS request hitting a GPC fault gets Completer Abort.

RME DA: Realm + DPT

Realm programming interface for assigning devices to Realms (CCA). The Device Permission Table checks PA granules against VMIDs for ATS Translated traffic (which skipped translation), giving VM isolation even when the device holds translations. Invalidate with CMD_DPTI_*.

Security-focused verification: the bugs that matter most here are isolation leaks: a Non-secure stream reaching Secure PA space, a stale TLB entry crossing a VMID or StreamWorld, Translated ATS traffic from an untrusted device bypassing checks, or GPC applied to the input address instead of the output. Build negative tests and assertions for each.

10

Inside the design

The spec defines behaviour. Microarchitecture is where most bugs live. For a senior role, be ready to sketch this pipeline and point at the hazards.

Performance levers

  • TLB reach: large pages, contiguous hint, range TLBI.
  • Hit-under-miss and miss-under-miss per stream.
  • Miss coalescing so 64 DMA beats to one page do one walk.
  • Walk cache levels and S2 caching for nested.
  • Prefetch commands for latency-critical streams.

Hazards to design around

  • Invalidation racing an in-flight walk: the walk must not fill a stale entry after the TLBI completes.
  • CMD_SYNC must drain all transactions translated by now-invalid entries.
  • Same-ID ordering when hits pass misses.
  • HTTU RMW atomicity versus CPU writes.
  • Stall + queue-full + SMMUEN off interactions.

Integration

  • Clocks/power: idle ports, Q-channel, retention of TLBs.
  • Coherent table walks (CR1 attributes) vs non-coherent with cache maintenance.
  • MSI path loops back through the SMMU fabric.
  • RAS: ECC on TLB RAMs, error records, poison propagation.
  • PMCG counters for TLB miss, walk count, latency.

Verification playbook

Checker strategy

  • Translation checker: for each egress beat, prove there is a mapping that existed between the txn's arrival and the last CMD_SYNC completion that permits this PA and attributes.
  • Invalidation checker: after CMD_SYNC completes, no egress may use a mapping invalidated before it. This is the single most valuable check.
  • Event checker: exact record contents, one event per txn, fault priority, and no events for prefetch or Config=abort.
  • Queue SVA: PROD/CONS wrap, full/empty, overflow flags, CONS.ERR stop.
  • Isolation checker: output PA space vs SEC_SID, GPC, DPT.

Coverage model (crosses that find bugs)

  • STE.Config × Security state × StreamWorld × EATS
  • Granule × levels × block/page/contiguous × TxSZ edges
  • Fault type × stage × terminate/stall × A/R bits
  • Command type × scope (VA, range, Leaf, TTL) × concurrent traffic hitting that scope
  • Queue: empty, full, wrap, overflow, error at each position
  • Linear vs 2-level stream table at SPLIT boundaries
  • ID-register configuration (each optional feature on/off)

Formal is a good fit for

Queue pointer and wrap logic, GERROR/GERRORN handshake, TLB multi-hit freedom, miss-tracker deadlock freedom, ordering rules on egress.

System-level / emulation

Boot Linux with arm-smmu-v3 driver, VFIO passthrough, SVA with a real device model. Finds driver-visible ordering and performance bugs that unit-level random misses.

Sign-off metrics

Code + functional coverage closed per IDR configuration, zero open checker waivers on invalidation, performance targets (miss latency, walks/cycle, TLB hit rate) met on traffic profiles from real workloads.

Interview drill

Answer out loud first, then open. Answers are short on purpose: this is the level of detail a strong senior candidate gives before the interviewer asks for more.

Q01Why did SMMUv3 move configuration into memory?

v2's register context banks capped the number of concurrently live streams (a few hundred at most). Systems with thousands of PCIe functions and many processes per device need every stream always configured, since DMA can start any time. In-memory Stream Table/CD tables scale with memory, and the SMMU caches what is hot.

Q02Walk me through a translation from transaction to PA.

SID → STE (via linear or 2-level stream table). Check V and Config. If S1 enabled and SSID valid → CD (via CD table, through S2 if nested). Check TLB with StreamWorld/VMID/ASID/VA tag. On miss, S1 walk with each table address translated by S2, then S2 walk of the output IPA. Apply permissions, attributes, MPAM, GPC. Emit PA or fault.

Q03How many memory accesses does a cold nested walk take?

(n+1)(m+1)−1; 24 for 4-level by 4-level, plus the STE and CD fetches (and the CD fetch itself needs an S2 walk). Walk caches and S2 caching exist to cut this down.

Q04What does CMD_SYNC guarantee, exactly?

When it completes, all prior commands in the queue have completed, including their effect on in-flight transactions: no transaction will use an invalidated config or translation, and outstanding ATC invalidations have finished. Completion is signalled by MSI, SEV, or observed by CONS passing it.

Q05Why ATC invalidation after the SMMU TLB invalidation, not before?

If you clear the ATC first, the device can immediately send a new Translation Request that hits the still-stale SMMU TLB and repopulate the ATC with the old mapping. TLBI → SYNC → ATC_INV → SYNC closes that window.

Q06Stall vs terminate: when would you use each?

Stall holds the faulting transaction so software can fix the mapping and RESUME, giving demand paging for devices that tolerate long latency. Terminate aborts (or RAZ/WI) immediately. Never stall PCIe: stalled posted writes can block the fabric and deadlock. PCIe uses ATS + PRI for the same goal.

Q07What happens if the Event queue is full?

Events not tied to stalls are discarded and overflow is flagged by toggling PROD.OVFLG. Stall events are not discarded: the stalled transaction waits, retries, or records later when the queue becomes writable. Interview bonus: STE.Config=abort and prefetch errors never record anyway.

Q08How does SVA work with an SMMU?

The device's PASID maps to a CD whose TTB0 and ASID are the process's own page tables and ASID. With BTM the SMMU snoops the CPU's TLBIs, so the kernel's normal munmap path also clears SMMU TLBs. With ATS/PRI the device can fault pages in on demand.

Q09What is a StreamWorld and why does it exist?

The translation regime a stream belongs to (NS-EL1, EL2, EL2-E2H, Secure, EL3), set by STE.STRW and Security state. It tags TLB entries so TLBI commands and broadcast TLBIs hit exactly the entries of the regime they target, just like the CPU's TLB regime tagging.

Q10Name the bug you'd worry about most in an SMMU and how you'd catch it.

A walk in flight across an invalidation filling a stale TLB entry after CMD_SYNC completed. It produces a wrong PA silently. Catch with an invalidation-aware scoreboard (every egress after SYNC must use a mapping valid after the invalidation), directed race tests with controllable memory latency, and coverage that the TLBI scope actually overlapped in-flight walks.

Q11How do you build a reference model when caching makes outcomes non-deterministic?

Keep a timestamped history of every table and config write. For each transaction, compute the set of legal translations from snapshots between its earliest observation point and the last completed sync. Pass if the DUT's result is in the set. Also check fault reporting is consistent with the chosen snapshot.

Q12What is split-stage ATS?

STE.EATS=0b10: ATS completions return the stage-1 result (IPA) only. Translated transactions still go through the SMMU's stage 2. The hypervisor keeps control of VM isolation while the device caches guest translations.

Q13How does RME change the SMMU?

Adds a Root programming interface and Granule Protection Checks on every output PA against the GPT, the same structure the CPUs use. A GPC fault looks like an external abort to the device and is not recorded in the Event queue. RME DA adds the Realm interface and the DPT for isolating ATS Translated traffic.

Q14Compare a CPU MMU, an SMMU and a GPU MMU.

CPU MMU: context from system registers, synchronous precise faults, TLBI + DSB + ISB. SMMU: context from the transaction's IDs and in-memory tables, asynchronous fault reporting via queues, commands for maintenance, many concurrent streams, ATS/PRI. GPU MMU (vendor-specific): huge parallel miss rates, large page sizes, replayable faults through a fault buffer, often sits behind or alongside an SMMU in the SoC for system-level isolation.

Q15How would you verify the command queue in isolation?

Drive random command streams with random PROD updates, sizes and wrap points; SVA for full/empty and pointer monotonicity; inject illegal opcodes and aborts at every position to check CONS.ERR, GERROR and the restart flow; cover CMD_SYNC completion modes; and check that consumption order matches issue order for commands with visible side effects.

Q16What does SMMUEN=0 do?

Translation is off. Incoming transactions follow SMMU_GBPA: bypass with overridden attributes or abort. Queues can still be enabled (SMMUEN=0 does not imply EVENTQEN=0). Transitioning SMMUEN to 0 terminates stalled transactions. Reset value of GBPA.ABORT is implementation choice, which matters for secure boot.

Q17How do you make one testbench cover many SMMU configurations?

Read IDR0–IDR6, AIDR and the S_/R_/ROOT_ ID registers at the start of each test; use them to constrain stimulus, enable checkers, and select coverage groups. Keep a regression matrix across RTL parameter sets so each optional feature is exercised both present and absent.

Q18What is the contiguous bit and why does it matter for verification?

A hint that 16 (4K granule) adjacent entries map a contiguous, aligned region with identical attributes, so the TLB can hold one entry. Bugs appear when software misprograms it (not all entries identical): architecture allows constrained-unpredictable results, and the TLB conflict path must still behave legally. Cover TLBI of one page inside a contiguous range.
